
===== 第 1 页 =====
LLM 如何利用超图 RAG 中的电影拍摄规则提升 Blender 白模预演质量而不牺
牲泛化
直接答案（TL;DR）
不要让规则” 命令”LLM 怎么拍，而要让规则在四个不同的通道里各就各位：几何与语法正确性交给确定性校验器/求解器
（硬约束，不进 prompt） ；镜头结构交给” 散文分镜式中间层 + 约束解码”（半硬） ；风格与惯例以” 原则 + 适用条件
+ 例外 + 强度” 的形式检索进 prompt（软引导） ；最后用规则评分器和VLM 评审做生成后把关（裁判而非命令）。
同时把知识库里的规则建成可废止（defeasible）的超边——每条规则自带条件、例外、优先级与置信度，并把” 经典破
例案例”（如库布里克越轴）作为一等公民入库。这样 LLM 保持创作自由度，规则负责兜底和纠偏，系统既比纯自由生成
更专业，又不会退化成 1996 年 DCCL 那种” 只能演 16 个 idiom” 的僵硬专家系统。
1. 问题诊断：为什么” 规则进 RAG” 容易变僵硬
1.1 电影拍摄规则在认识论上就是” 默认规则”，不是定律
电影语法的主体不是物理定律，而是 惯例（convention）与惯用手法（ idiom）。早在 1996 年，Christianson 等
人的 DCCL（Declarative Camera Control Language ）就把 Arijon 教科书里的 16 个惯用手法编码成声明式语
言，由编译器求解几何约束、再由启发式评分器挑选 ” 最佳” 手法，其核心评分项甚至包括 ” 消除越轴的片段 ”(DCCL,
AAAI’96)。这条路线证明了规则可以被形式化，但也暴露了它的天花板：idiom 库是封闭的，遇到库中没有的情境系统就
无能为力——这正是” 僵硬” 的原始形态。同一时期的 Virtual Cinematographer 用分层有限状态机实现 idiom，靠”
遇异常就退回更一般的 idiom” 的机制来缓解，但本质上仍是枚举式覆盖 (Virtual Cinematographer )。
更关键的是， 电影规则天生带例外。180 度规则要求摄影机始终停留在动作轴线的一侧以维持空间方向感， 但 《闪灵》 的浴室
戏、 《圣女贞德蒙难记》 、 《精疲力尽》都因故意越轴而成为影史经典——破例本身就是表达手段 (Wikipedia: 180-degree
rule)。 知识表示领域对这种” 有例外的规则” 早有成熟的形式化：可废止逻辑 （defeasible logic ）区分严格规则 （strict
rules） 、可废止规则（defeasible rules ）与阻断者（defeaters） ， 用规则间的优先级关系解决冲突， 且天然支持” 更具体的
规则优先于一般规则” 的特异性原则 (Stanford Encyclopedia of Philosophy )。结论是：你的超图知识库如果只存” 规
则 → 做法” 而不存” 何时适用、何时失效、谁覆盖谁”，那么无论检索多精准，注入 LLM 后都必然僵硬——因为知识本
身被压扁成了定律。
1.2 工程层面的三个” 僵硬放大器”
即使知识建模正确，工程上还有三个会把规则变僵硬的放大器。第一是 prompt 规则堆积：把所有检索到的规则塞进系统
提示词， 会引发指令冲突与注意力稀释——实证研究表明， 多约束并存时模型往往” 满足一条、 悄悄违反另一条”， 长上下文
中还存在 lost-in-the-middle 效应， 早期设定的规则在长对话后会被淡忘(Deepchecks)。OpenAI 开发者社区也有专门
讨论” 更多指令反而损害模型表现 ” 的反模式 (OpenAI Community )。第二是用错约束层级：约束解码（constrained
decoding）能在 token 级别保证输出符合 JSON Schema ，XGrammar 的掩码计算已低至 40 微秒以下，但它只保证
结构合法，不保证语义正确 ——一个语法完美但机位荒谬的分镜可以畅通无阻 (GMI Cloud )。把” 镜头语言” 这种语义
层面的规则硬编码进语法层，等于把创作空间也一起锁死。第三是 检索失配：RAG 的精度天花板由知识层的信噪比决定，
检索到过时、冲突或碎片化的规则时，“prompt 工程救不了知识问题”(Brainfish)。这三个放大器共同指向一个设计原则：
规则必须按” 约束性质” 分流到不同的注入通道，而不是统一以文本形式灌进 prompt。
2. 知识表示：把电影规则建成” 可废止的” 超图

好适合表达这种多元关系——HyperGraphRAG 用超边表示 N 元事实，检索时对实体与超边做双向邻域扩展，在医疗、
法律等规则密集型领域已证明优于二元图 RAG(HyperGraphRAG, NeurIPS 2025 )。
三层结构带来两个直接收益。其一，检索粒度可调：动作戏场景检索中层 idiom 为主，微调阶段只取底层参数，避免一次性
把整本教科书塞进上下文。其二， 泛化有了锚点 ：当 LLM 遇到知识库没有覆盖的情境时，它不必 ” 没有 idiom 就宕机”
（DCCL 的老问题） ，而是退到顶层原则做推理——原则是少见的、真正接近” 定律” 的知识，正好交给 LLM 的常识与叙
事推理能力去展开。
2.2 超边模式：条件、结论、例外、强度、先例
每条规则超边建议包含以下槽位： 条件（适用情境的结构化描述：场景类型、角色数、情绪基调、节奏） 、结论（推荐做法，
指向中层 idiom 或底层参数） 、例外（已知失效条件） 、强度（strict / default / weak preference 三档，对应可废止逻
辑的严格规则、默认规则与弱偏好） 、优先级（与同域规则冲突时的覆盖关系） 、先例（遵循或打破该规则的经典影片证据，
如” 轴线规则” 超边的例外槽挂上《闪灵》浴室戏） 。DCCL 的启发式评分器实际上就是” 例外与惩罚项” 的雏形——它惩
罚过短过长的片段、消除倒摇镜头，且每个 idiom 都声明自己适用的活动类型 (DCCL, AAAI’96 )。把这些元数据显式
建模，检索阶段才能做” 情境匹配” 而非” 关键词匹配”。
要特别注意破例先例的价值。电影教育本身就强调” 先掌握规则，才有资格打破规则”，而专业实践中破例有明确的章法：切
一个中性镜头过渡、在镜头内运动过轴、越轴前先建立空间关系 (Cadrage, DINFOS)。把这类” 合规的破例手法” 作为
独立超边入库，LLM 在需要制造迷失感、情绪突变时就能 引用先例来辩护自己的破例，而不是被规则一票否决。这是” 不
僵硬” 最实质的知识层保障：泛化能力不是来自忽略规则，而是来自知道规则的边界。
3. 检索策略：从” 按问检索” 到” 按戏检索”
3.1 情境指纹：先理解这场戏，再检索规则
剧本到预演的检索单元不应是句子，而应是情境。管线第一步由 LLM 把剧本解析为场景、节拍（beat）与动作单元，并为
每个单元抽取” 情境指纹”：场景类型（对话/追逐/独白/群像） 、参与者数量与空间关系、情绪曲线位置、运动矢量、对白密
度。FilmAgent 的实践佐证了这一分工的价值——它把虚拟制片拆成创意开发、剧本、摄影三阶段，由导演、编剧、摄影
等角色 agent 协作，并用 Critique-Correct-Verify 与 Debate-Judge 两种多智能体算法减少幻觉，最终在人类评测中
以均分 3.98/5 超过所有基线 (FilmAgent)。 情境指纹就是检索超图的查询向量：先以” 双人、 室内、 对峙、 情绪升温” 匹
配中层 idiom 超边，再沿超边扩展到相关的原则、参数与例外。
这里有一个反直觉但重要的建议：宁缺毋滥。为每个节拍检索 top-k 条最相关规则（经验上 3~8 条为宜） ，而不是追求召回
率。原因有二：一是前述的指令冲突与注意力稀释问题；二是电影规则的密度本身极高，一个对话场景可适用的规则数以十
计，全量注入等于把 LLM 变成查表机器。可以把” 规则预算” 作为显式参数：探索模式（导演想要灵感）少注入、多采样；
合规模式（用于拍摄参考的技术预演）多注入、严校验。这正好对应预演的本质 ——“预演只回答那个昂贵的问题，而不是
所有问题”，过度预演本身就是业界公认的浪费 (Storyflow)。
3.2 双向扩展、去重与冲突消解
超图检索的优势在邻域扩展： HyperGraphRAG 先以向量相似度检索实体与超边，再做 ” 实体 → 超边” 与” 超边 →
实体” 的双向扩展，组装出完整的 N 元事实集 (HyperGraphRAG, NeurIPS 2025 )。映射到你的场景：从 ” 正反打”
idiom 超边扩展到它连接的原则 （视线匹配） 、 参数 （内外反打机位、 景别序列） 与例外 （第三人入场时退回群像idiom） 。 但
扩展必须配合装配 （assembly） 步骤： 对检索结果按语义去重， 按强度与优先级做冲突消解——若” 保持轴线”（default）

4. 注入通道：四条通道各司其职（核心设计）
4.1 通道光谱总览
Figure 1: 规则注入通道的刚性-泛化光谱
上图把六种注入方式按约束强度排列成光谱。核心论点是：“提高质量” 与” 保持泛化” 不是单旋钮的此消彼长，而是可以
把规则拆到不同通道上分别实现 。硬性程度应该与” 违反后的失败成本” 挂钩：语法错误会让 Blender 脚本报错（立即失
败、零价值）→ 用最强的约束解码；越轴、穿模、主体被遮挡是视觉错误但可检测 → 用确定性校验器兜底；构图平庸、情
绪不匹配是质量问题而非错误 → 用评审回路打分；而” 这个镜头该用什么景别” 根本没有唯一正确答案 → 只给软引导。
4.2 硬约束通道：几何校验器与求解器（规则不进 prompt）
物理与几何类规则 ——不越轴（除非声明破例） 、主体不被遮挡、不穿模、摄影机不穿墙、安全边距 ——不应该出现在
prompt 里，而应实现为对 Blender 场景状态的确定性检查器或约束求解器。理由很硬：约束解码与 prompt 都只能影
响” 文本”，而越轴与否是世界状态的函数， LLM 根本看不到渲染结果，让它在生成时 ” 自觉遵守” 几何规则是把可验证
的问题交给不可验证的通道。SceneCraft 的路线是范本：LLM 把空间关系写成数值约束交给专门求解器解算布局，渲染
后再由多模态 LLM 检查图文对齐并迭代修复，相比 BlenderGPT 基线在 CLIP 分数上提升 40~45%(SceneCraft)。
NVIDIA 的 Scenethesis 同样采用” 优化模块强制物理合理性 + 场景裁判模块验证空间一致性、不满意就重来” 的双保
险 (Scenethesis)。
这类硬约束还是 ” 反僵硬” 的隐形功臣：当几何正确性由校验器保证， prompt 里的规则就可以放心地只谈美学与叙事，
LLM 的创作空间反而更大。DCCL 当年的洞察至今有效——其编译器” 完全领域无关，只依赖几何”，而 idiom 库” 可
复用于任何双角色互动的动画”(DCCL, AAAI’96 )：几何归编译器，叙事归 LLM，这个分工三十年后依然是最优解。

4.3 半硬通道：散文分镜中间层 + 约束解码
在” 自由文本” 与”Blender API 调用” 之间，强烈建议插入一个 镜头中间层 ：每个镜头一句结构化散文，描述景别、角
度、主体在画面中的位置、摄影机运动及其时机。 Ronfard 等人的 Prose Storyboard Language （PSL）证明了这条
路线的可行性：它用 ” 一个镜头一个句子 ” 的形式语言描述电影，词汇直接借用片场实践（ ECU/CU/MS/LS 、pan/
dolly/crane、screen left/right ） ， 人机共读、 可解析为无歧义语义， 且能表达任意复杂的运动镜头(Prose Storyboard
Language)。 让LLM 先输出 PSL 式分镜、 再编译为Blender 操作， 比直接生成Python 有三大好处： 中间层可读（导
演能审） 、可检索（分镜句与规则超边天然对齐） 、可约束（PSL 的句法可以做约束解码，把” 非法镜头描述” 在 token 层
面清零） 。
约束解码在这里用在刀刃上：现代实现中 XGrammar 对 JSON Schema 的掩码计算低于 40 微秒，llguidance 约 50
微秒/令牌， 甚至可因跳过采样而快于自由生成(GMI Cloud)。 但要牢记它的边界——结构合法不等于语义正确，Schema
设计应” 扁平优先、 必填优先、 枚举优先”， 深层嵌套与条件依赖会显著推高失败率(GMI Cloud )。 因此中间层的Schema
只锁” 词汇与语法”（合法的景别枚举、合法的运镜动词） ，绝不锁” 选择”（用哪个景别是 LLM 的自由） 。这条分界，就
是” 不僵硬” 在结构层的精确含义。
4.4 软引导通道：规则包进 prompt 的正确写法
检索到的规则以软引导进入 prompt 时，写法决定刚柔。三个要点。第一， 写成” 原则 + 理由 + 例外”，而非祈使句。
“对话场景通常用正反打， 因为反方向的视线能让观众确认两人在对视； 当需要表现关系破裂或迷失感时， 可考虑越轴——见
《闪灵》” 这样的表述，LLM 会把规则理解为” 有理据的默认项”，遇到剧本中” 两人背对背沉默” 的戏自然会推理出例外。
第二，正负例成对给出。idiom 超边同时挂” 遵循先例” 与” 破例先例”， 检索时一起注入， 等于给LLM 提供了案例推理的
素材——这比抽象规则更符合 LLM 的少样本学习特性。 第三，声明规则强度。 把default 规则标为” 通常”，strict 规则
标为” 除非声明破例否则必须”，让 LLM 自己掌握让步空间。HOG-Layout 在 3D 场景生成中采用了同款思路：LLM
结合向量库检索的设计规则生成初始布局，再由 VLM 分层迭代优化 (HOG-Layout)。
还要注意双向 prompt 契约：要求 LLM 在每个镜头的决策中标注” 引用了哪些规则、哪些是有意违反及理由”。这既是
可解释性（导演审稿时能看出 AI 的意图） ，也是反僵硬的制度化设计——破例被显式允许并要求辩护，规则就从 ” 天花
板” 变成了” 谈判桌”。FilmAgent 的 Debate-Judge 机制（摄影 agent 与导演 agent 辩论机位、由裁判定夺）本质
上是把这种辩护过程多智能体化 (FilmAgent)，在单 LLM 实现里用 CoT 辩护字段即可获得大部分收益。
4.5 裁判通道：规则评分器 + VLM 评审的双回路
生成后把关是” 软规则” 最可靠的落地形态， 因为裁判不限制生成空间， 只给反馈。 建议双回路： 内回路是规则评分器——把
知识库中可程序化的规则（越轴、 切点时长、 景别跳跃幅度、 屏幕方向一致性）实现为对分镜中间层与Blender 场景状态的
检查函数，输出结构化违规清单；外回路是 VLM 评审——把渲染帧与叙事意图一起给多模态模型，评价构图与情绪表
达。DCCL 的启发式评分器当年就是这么做的：为每个候选 idiom 打分、剪掉越轴和过短的片段，且作者明确指出” 视觉
质量由手法与演员运动的几何互动决定，无法离线预估”(DCCL, AAAI’96 )——这正是评审回路必须存在的原因。
自我批评有已知局限：无外部验证信号的纯自我修正，模型常把对的改错，可靠的修正需要外部校验器做后盾 (Test-Time
Scaling Cheatsheet )。所以规则评分器（确定性）与 VLM 评审（外部视角）缺一不可。成本上可采用条件修正策略：只
有评分器报违规才触发重生成，全流程 token 成本约为单次的 1.6~3 倍 (Hinterbuild)。评审回路的另一个副产品是训练
数据飞轮：每次” 违规 → 修正” 的对照样本，都是后续微调或偏好优化的素材。

评审端构成双回路：渲染帧先过几何校验器（越轴 /遮挡/穿模的确定性检查） ，再过规则评分器（对中间层的程序化规则检
查） ，最后过VLM 评审（构图与叙事意图） 。任一环节报出严重违规即带诊断信息回到”LLM 导演” 重新决策；轻问题则
只记录供导演参考。 CinePreGen 把预演生成与相机可控性结合、 CinemAssist 在关键帧与场景两级生成构图提案供人
选用，都印证了” 生成—评审—再生成” 回路是当前预演 AI 的主流骨架 (CinePreGen, CinemAssist, UIST’24 )。
5.2 技能库沉淀：让系统越用越聪明而不越用越僵化
每次评审通过的镜头方案（情境指纹 + 分镜中间层 + Blender 参数 + 评审分数）回写为一个 可复用 skill。这正是
Voyager skill library 的范式：成功行为被存为可执行代码，按语义嵌入检索，遇相似任务直接复用或组合，形成可组合
的能力增长 (Voyager)；SceneCraft 也把” 从合成查询自动学出的空间技能库” 作为其核心贡献之一 (SceneCraft)。在
你的体系里，skill 库与规则超图是互补的两层记忆：规则超图是” 先验的、 演绎的”（教科书知识） ，skill 库是” 经验的、 归
纳的”（本系统实测有效的解法） 。检索时两者并排呈现，LLM 可以” 照方抓药”（高相似度情境直接复用 skill） ，也可以”
据理创新”（低相似度时退回原则层推理） 。
这里有一条防僵化的纪律：skill 只作为建议出现，从不作为默认覆盖项 ，且每个 skill 记录其适用情境指纹与历史评分分
布。当用户多次手动修改某类 skill 的输出，该 skill 的检索权重应自动衰减——把人类导演的修正行为变成知识库的自我
更新信号。这样知识层就闭环了：规则来自教科书，经验来自使用，两者都带强度与置信度，系统随使用演化而非固化。

分最高的排前面，但低分候选保留展示，因为很多” 低分” 恰是有意破例的创新镜头。Best-of-N 加重排序是推理期提质的
生产标准做法 (Agent Optimization Survey )，配合” 违规才重试” 的条件修正策略，成本可控。
7. 质量评估体系
7.1 三层指标：合规、质量、多样性
评估必须覆盖三个维度，且三者张力本身就是 ” 不僵硬” 的度量。合规层：规则违反率（越轴次数/场景、遮挡率、穿模率）
与 Schema 解析失败率——后者在生产中应接近零，且应与语义错误分开统计 (GMI Cloud )。质量层：VLM 评审分数
+ 人类导演盲评（与” 无规则注入” 的消融组对比） 。多样性/泛化层：同一剧本多次生成的分镜差异度、OOD 场景（知识
库无覆盖的情境类型）下的可用率——这一层是” 不僵硬” 的直接证据，DCCL 式系统在这一层会得零分。
特别提醒 VLM 评审的当前能力边界：ShotBench 基准（覆盖景别、构图、运镜等 8 个摄影维度、3.5k+ 专家标注问答）
显示，最强的通用 VLM（GPT-4o）平均准确率仅 59.3%，约半数受测模型低于 50%，运镜维度甚至接近随机；经摄影
语料专训的 ShotVL（3B） 可达65.1%(ShotBench, ShotBench GitHub)。 这意味着 VLM 评审现阶段适合做” 粗
筛与相对比较”，不适合做唯一裁决——关键决策仍需人类导演或确定性规则兜底。若预算允许，用 ShotQA 这类 7 万级
摄影问答数据微调一个专用评审模型，是性价比很高的投资 (ShotBench)。

7.2 消融实验设计
建议的验收实验矩阵：以 20~30 个类型各异的场景（双人对话、追逐、群像、独白、动作）为测试集，四组对照——（A）
无规则注入纯自由生成； （B）规则全量灌 prompt（模拟” 僵硬路线”） ； （C）本文四通道方案； （D）C 去掉破例先例与规
则分级（验证知识建模的贡献） 。比较四组的规则违反率、人评质量分、分镜多样性。预期结果是：B 组合规最高但多样性
与人评” 创意性” 最低；C 组在合规接近 B 的同时保持接近 A 的多样性——这正是” 既高质量又不僵硬” 的可证伪定义。
Runway 对 AI 预演工作流的行业观察也支持这个测试设计：预演的一半价值在” 回答这场戏成不成立”，另一半在” 告诉
剧组该搭什么”，评估应分别覆盖这两半 (Runway)。

9. 落地路线图与风险
9.1 三阶段路线图
第一阶段（2~4 周，可用原型）：只做通道四（规则评分器）与通道二（中间层 + 约束解码）的最小实现。定义 10~15 条
核心规则（轴线、 视线匹配、 景别跳跃、 切点时长） ， 实现PSL 式中间层 Schema 与 Blender 白模执行器， 评分器先只查
越轴与遮挡。此阶段即可量化对比” 有/无规则评分回路” 的质量差，验证整条管线的价值假设。第二阶段（1~2 月，知识
层成型）：把规则迁移为带条件 /例外/强度的超边，接入你已有的超图 RAG，实现情境指纹检索与规则包装配， prompt
侧引入” 原则 + 例外 + 强度” 写法与破例辩护字段。第三阶段（持续）：接入 VLM 评审回路（关注 ShotBench 揭示的
运镜维度弱项，必要时专训） 、技能库沉淀与衰减机制、多样性预算与Best-of-N rerank ，并按第 7 节的消融矩阵建立回
归评测。
