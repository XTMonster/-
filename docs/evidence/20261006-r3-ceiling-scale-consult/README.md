## 0. 为什么问这一件事

* 红线 **E1 ≥ 0.70** 的产品口径是"**前 3 行**里相关的条数 / 3"（`tools/knowledge/e1_panel.py`）。
* 已入库的"完美重排上限"证书 **0.7760** 是在 **`--top-k 20`** 的跑上算的
  （`docs/evidence/20261006-e1-ceiling/`），即"完美重排器从 **20** 条候选里挑最好 3 条"。
* `docs/evidence/20261006-e1-judge-context/`（P14-199）实测：同一检索、同一批 192 个
  `(query, case_id)`、`excerpt/zh` 逐字节相同、面板与判分提示词 sha 相同，
  **只差 `--top-k`** ⇒ 0.1927（k=3）↔ 0.2812（k=20 的前 3 行），两位评委**同向上升**。
  ⇒ 评委给分随"这次调用看到几条候选"漂移，跨 `--top-k` 的 E1 不可比。

于是"**0.7760 ≥ 0.70 ⇒ 结构可达**"这句话是在**另一把尺子**上量出来的。

## 2. 两侧对拍（四栏，见 `panel.md` / `panel.json`）

GLM-5.3 侧新增（DeepSeek 侧**没有**提出）的关键判词：

1. **0.7760 是系统性乐观的高估**：它的相关标签全产自"每次调用看 20 条"的语境，
   而红线在"每次调用看 3 条"的语境里量；因语境越大分越高，证书相对红线**偏乐观**。
2. **判分语境被 `--top-k` 一个旋钮绑死**：要"固定 C=3、报 K"，前提是面板能把
   "每次判分调用喂几条"从 `--top-k` 里拆出来；当前两者耦合，所以任何"扩大 K"的跑
   都同时改了 C，量出的上限天然不同尺。**`e1_ceiling_report.py` 本身不用改。**
3. **缺的那个量**：K=20 的 1,280 行全是 C=20 标签；排名 **4–20 的 1,088 行
   （64×17；64 = 1280/20 = 192/3）在 C=3 语境下完全未知** ⇒ 只用现有产物定不了案。
4. **最小新测量**（见 §3）。
5. **`report()` 没记"每次调用几条"与提示词 sha**：尺度事后不可追溯；
   同尺证书必须把被固定的那个旋钮写进产物。

## 3. GLM-5.3 给的最小可执行测量（**零新检索、零改判据**）

把 **K=20 那一跑的候选内容（`excerpt` 逐字节沿用）**按每查询、按检索序切成**连续三元组**
（取 ranks 1–18；19–20 只剩 2 条、属另一种语境，**不入主证书**），以 **batch=3、
同一判分提示词 sha** 重判，合并成一个打分文件，再调
`e1_ceiling_report.py --top-k 3` 读 `ceiling`。

* 命令形状：`python tools/knowledge/e1_ceiling_report.py <relabeled>.jsonl`（`top_k` 默认 3）
* **判据**：`ceiling ≥ 0.70` ⇒ 该池可达；`ceiling < 0.70` ⇒ **该池不可达**；
  `|ceiling − 0.70| ≤ 0.016` ⇒ 原样重复一次再判（0.016 ≈ 1/64，一条查询的粒度）。
* **不动的**：红线 0.70、相关阈值 4.0、分母（前 3 行）、`SCORE_WEIGHTS`。

### 3.1 与仓库现状的差口（**需要一次仪器改动，必须单独冻结**）

主线在仓库里核这条计划的落地形状：

* `e1_panel.py::_score_one`（`tools/knowledge/e1_panel.py:325`）**把最终 `top_k` 条
  直接交给 `judge()`**（`:364` `verdicts[name] = judge(client, query, cases)`），
  所以"判分调用里几条" **== `top_k`**。`--rerank-retrieve-k K --top-k 3` 能让**检索**取
  K 条、但**判分**仍只看重排后的 3 条 ⇒ 它给出的是"某个重排器选出的 3 条在 C=3 语境下"的分，
  **不是**"池里 18 条在 C=3 语境下"的分。
* 所以 GLM 那条"按 3 条一呼重判冻结候选池"需要一个**新的判分模式**（把"每次调用几条"
  从 `--top-k` 拆出来），落在 `e1_panel.py`。按本仓纪律这属**仪器改动** ⇒
  要单独显式重新冻结 `tests/plan_v4_instruments.sha256.json` 并写理由。
* 这也正是 GLM 第 5 条要求把 C 与提示词 sha 写进产物的原因——否则"哪把尺子"事后只能靠重做配对实验才知道。
