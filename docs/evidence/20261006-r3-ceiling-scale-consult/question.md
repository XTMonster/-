# 问题：与红线同尺度的“完美重排上限”该怎么定义（只问这一件事）

## 已知事实（都可复算）

1. 红线：**E1 ≥ 0.70**。E1 的产品口径＝“**前 3 行**里相关的条数 / 3”，
   相关＝两位 LLM 评委（deepseek-chat + glm-5.3）1–5 分**均值 ≥ 4.0**。
2. 已入库的“完美重排上限”证书在 `--top-k 20` 的跑上算得 **0.7760**
   （工具口径：`mean(min(3, 该查询在候选里的相关行数)/3)`，即“完美重排器从 K 条候选里挑最好 3 条”）。
3. 新实测 P14-199：同一条检索、同一批 192 个 `(query, case_id)`、`excerpt/zh` 逐字节相同、
   面板与判分提示词 sha 相同，**只差 `--top-k`**：
   * `--top-k 3` → **0.1927**；同语料控制跑 → **0.1771**
   * `--top-k 20` 的**前 3 行** → **0.2812**
   两位评委**同向上升**（deepseek 2.536→2.831、glm 3.024→3.133）。
   ⇒ **评委给分随“这次调用看到几条候选”漂移**；跨 `--top-k` 的 E1 不可比。
4. 推论：K=3 时候选集就是那 3 条，任何置换同集合 ⇒ 上限恒等于 E1 ≈ 0.18–0.19；
   要够 0.70 只能靠**扩大 K**，而 K 变了判分语境也变了。

   必须写成两个独立旋钮？一个能直接对红线说话的证书，应该固定哪一个、报哪一个？

3. 给出**最小**的一次新测量：命令、K、判分语境、要报的量、判“可达/不可达”的判据。
   红线 0.70、阈值 4.0、分母（前 3 行）**都不许动**。
