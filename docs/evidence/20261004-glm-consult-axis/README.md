## 逐条判词（模型的话不算事实）

### F1「A 选①：线随当前连线、继承侧别；② 是把指标做绿」——**采纳方向，但按 F2 收边界**

它给的实务理由是"180° 约束落在**覆盖**（机位怎么摆）而不是**调度**（人怎么走）"。
仓库里能核的部分：R001 的消息确实同时给两条出路（"改走位或机位角度，或按 §6.2
插入中性镜头过渡"），而 §6.2 的 `axis_neutral` 卡片确实把中性机位定义成**合法的
跨轴桥梁**——**这条桥梁在判据里没有兑现**（中性只报 warning，换侧仍判红）。
⇒ 采纳"①方向正确"，但**不**照字面实现（见 F2）。

### F2「① 不能做成摆位与判据共用同一条线；真判据在剪辑点」——**证实（这条最有价值）**

我原本的方案正是"构建器按当前连线摆机位、规则也按同一条线判"——那会让 R001
**构造性成立**，规则不再独立检验任何东西（自证）。它给的正确形态：180° 在工艺上
是**相邻剪辑点**的性质（两人都在画时比屏幕左右顺序是否翻转；单人镜看的是视线/
运动方向），并且**跨线已在上一镜画面内可见、或其间有中性镜时应豁免**。
⇒ 这条直接改掉了我的实现方案：**规则要判屏幕方向连续性，而不是再算一遍同一条线**。

### F3「构图先查景别忠实度，再谈留白；修复提示要按维度拆根因」——**一半证实、一半已实现**

* **已实现**：`rule_checker` 的 COMPOSITION finding 本来就带上
  `composition.suggestions[:2]`（分项建议，例"主体在画面中的大小与景别不符"），
  修复提示词不是只有一句"分低于 70"。GLM 没见过这段代码，只能从 bundle 推断。
* **次序被实测改写**：我用 `work/_composition_items_probe.py` 在三份冻结工程上
  逐镜算了六个分项，弱项计数是 `rule_of_thirds` **61–63/64**、`framing` 13–33、
  `occlusion` 0–23 —— 主导项不是"景别忠实度"而是**三分线**。
* 于是按它的"查根因"思路往下挖（`work/_box_center_probe.py`）：主体盒中心的
  **中位纵向偏差 0.13**（横停在画面正中），即**竖直方向从没对准过三分之一**。
  照着做了一次扫描（`work/_aim_sweep_probe.py`，long12 的 40 个单主体镜）：
  对准点抬高 +0.1 / +0.2 m 的合计增益 **+130 / +214 分**，压低只有 +34 / +38
  ⇒ 取 **+0.15 m**，实测三份工程构图门 39/25/35（此前 41/21/24，合计 **+13**，
  见 `docs/evidence/20261004-aim-retest/`）。**`SHOT_FRAME.target_z`（§2.2 D2
  冻结常量）一个字没动**，只加了一层可测的取景偏移。
