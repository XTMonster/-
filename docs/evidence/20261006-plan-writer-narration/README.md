# GPT-6A"写计划"实测失败：它**没写计划，回了 524 字符的行动旁白**

日期 2026-10-06 21:0x–21:23。用户指令："**用 gpt6A 重新规划下一步执行计划**"。
这一跑**没有产出计划**——本目录是那次失败的原件与根因。

## 一、那次真跑留下了什么（逐字可查）

命令（`work/_run_replan.ps1`）：

```powershell
python -u tools/plan_writer.py --provider relay `
  --question work/_q_gpt6a_replan.md --question-only `
  --out work/_plan_replan/ --rounds 5 --max-prompt-chars 3100 --timeout 5400
```

| `plan.md`（1,332 B） | **不是计划**——是模型的**行动旁白** |

| `plan.round{1..5}.md` | **不存在**（精炼轮根本没写成） |

`plan.md` 的开头（逐字）：

> 我先按仓库真源做漂移检查：核对 `HEAD`、工作树、`AGENTS.md` 状态块…之后我会把用户提供的三条读数

`work/_replan.out` 只有一行（第 0 轮）＋ `exit=-1`；`_replan.err` **空**。

## 二、根因：**契约读起来像"给有工具的 agent 的指令"**

发出去的 system 是**写作契约全文**（~5 KB，hooks 里的 `plan-contract.md`），而那份契约的措辞是
"先做全量检索 → 逐行核对 → 留证 → 落点写清 `文件:行号`"——**它是对着"一个能动手的执行者"写的**。

通道这一侧只看得见那点上下文，于是模型把"指令"**演成了动作**：它以为自己在跑命令、在等终端，
于是**整轮都在描述"我将要做什么"**，没有写计划。**903 s** 的推理全花在这上面。

⇒ 这不是"模型不行"，是**我们给的 system 没说清它是谁**。

## 三、修法（代码 ＋ 守门）

`tools/plan_writer.py` 新增 `NO_TOOLS_NOTICE`，**拼在起草与精炼两侧 system 的最前面**：

> **你没有工具**：不能执行命令、不能读写文件、不能上网、也看不到任何仓库。
> 你**唯一**能做的是：读完这条消息里的内容，**直接把成品文本写出来**。
> 因此——**不要**写"我正在运行／我读取了／我先去核对"这类**旁白**；**不要**描述你打算怎么做，
> 直接**做**（也就是直接输出成品）；看不到的东西写"**材料未覆盖**"，不要猜。

守门：`tests/test_plan_writer.py::test_the_system_prompt_says_the_model_has_no_tools`
（钉住两侧 system 都以它开头、且含"你没有工具／旁白／材料未覆盖"三条）。`tests/test_plan_writer.py` **15 passed**。

**判据一个字没动**：这次改的是"**怎么把话说给模型听**"，不碰任何阈值／门限／分母。
