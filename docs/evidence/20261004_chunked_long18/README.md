`BudgetLimits.max_tokens = 2_000_000` 是 `budget.py:19` 的**硬编码默认**，
`driver._limits_from()` 只从配置映射 `max_llm_calls` / `max_cost_usd` /
`max_wall_seconds`——**没有任何配置键、也不随镜数缩放**。这与 §七十九 修掉的
"工具预算固定 200"是同一种缺陷（与场景规模无关的固定额度），只是这次由多轮修复
把它提前触发了：long17 已经用到 1.26 M，本来也只剩三成余量。

## 下一步（二选一，都要先量再定，不许闷着调）

1. **让额度跟着场景走**（与 §七十九 同形状）：给 token 上限一个
   `max(静态下限, 公式(镜数))` 的口径，并把 `max_tokens` 接进 `_limits_from`。
   代价是**真金白银**：long18 已经烧掉 200 万 token，64 镜跑满大约要 230 万。
2. **让多轮修复便宜下来**：续轮**只带最新一条观测**而不是整段对话，或把
   `repair_max_turns` 降到 2。省 token，但会牺牲"上一轮看过的东西还在"这条。

**不做**的事：把 `max_tokens` 直接抬到一个能跑完的数就当没事——那是把守卫当装饰，
和 §七十九 之前"固定 200 把修复饿死"是同一类问题，只是方向相反。
