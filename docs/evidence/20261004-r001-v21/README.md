# P14-77：轴侧状态机**顺序化**——构建器不再"猜"换位，两张表第一次合一

§73.3 把分歧的根因指到了构建器：它在**没有机位**的阶段就得决定从哪一侧摆机位，
于是用 `rotated ≥ 90°` 当替代判据（均匀方位先验下 **50% 猜中率**）。这一轮把那条
替代判据换成**量出来的事实**——顺序做，所以不需要迭代，也就没有会诊警告的固定点
收敛问题。

## 做法（一处真缺陷 ＋ 一处我自己的错）

1. `cinema/axis.pair_spans()` 抽出来（换位判据的原料：配对两点在每镜开始/结束时的
   位置），`crossing_events` 与构建器**共用同一份**——"结束位置 ≈ 下一镜开始"这条
   接力口径各写一遍必然漂。
2. `shot_builder.build_scene` 的摆机位循环改成**顺序状态机**：摆完这一镜的机位，
   就量一次"这一镜的连线扫没扫过这台机位"（两人同框才算看见）⇒ 决定**后续**镜头
   待在哪一侧；`_axis_sides_used` 记下每镜**实际用过**的侧别。
3. `rule_checker._axis_sides()` 改读构建器**实际用过**的那张表（相机是照它摆的，
   规则就该照它判）。构建器与规则从此读的是同一份事实，分歧不再靠"计划期近似"
   传话。

**第二件事差点是错的**：第一版只在**测到第一次扫过机位之后**才接管状态机，之前
继续用近似表。实测 `long9` 上近似表在第 27 镜多翻了一次（画面左右序判据证实不了
那次换位），而它在第 35 镜又翻回来——**两次翻转互相抵消**，两张表看着"差别不大"，
实际把 27–34 镜摆在了观众从没看见过的另一侧。初始化成"轴线自己的基准侧"之后，
分歧归零。

## 结果（同一支零 LLM 复评器）

| 工程 | 逐镜通过（近似 → 顺序） | R001 | 构图中位 | **构建器表 vs 真机位表** |
|---|---|---|---|---|
| long9 | 28 → **29** | 13 → **11** | 78.55 → **79.6** | 38 镜分歧 → **0** |
| long11 | 9 → 9 | 40 → 40 | 64.3 → 64.3 | 3 镜分歧 → **0** |
| long12 | 24 → 24 | 7 → 7 | 72.4 → 72.4 | 0 → **0** |

第三列那个"分歧 → 0"是这一轮真正的不变量：**构建器用的侧别表 ＝ 用真机位算出来的
表**（`used_vs_exact_diffs`）。long9 顺带三项都更好看，那是修对的副产物，不是目标。
