# P14-66：R001 必须说清**根因**——是机位摆错，还是"角色走位跨过了轴线"

**结论**：锚点（§六十三）与接力（§六十四）修好之后，`long9` 重建里仍会红的
**10 条 R001**，用 `work/_r001_probe.py` 一量就分成两类：

* **角色已经走到轴线另一侧**（`shot_020/036/039/041/047/049/...`）——
  `shot_020`：米迦尔在 (−4.11, 0.11)、伊恩在 (0.9, 0.0)，而机位 (−4.66, 2.95)；
  此时"拍到这张脸"与"待在轴线同侧"**不可能同时满足**；
* **人物还在轴线上但机位落在另一侧**（`shot_014`：两人仍在 (−0.9, 0) / (0.9, 0)，
  机位却在 (−1.48, 2.54)）——这是**主体朝向 × 请求侧别 × 固定轴线**的冲突，
  与 `station._honour_the_established_side` 的边界一致：镜像会把"正面"变成
  "背拍"，所以它保持模型要的方向、把冲突留给 R001 如实报（不静默改拍法）。

旧文案只有一句"把相机移到轴线另一侧"。修复回路照它去挪机位，修不动，白烧回合。

## 改法（`rule_checker.check_shot` 的 R001 分支）

出错的镜头里，凡是**有角色站在已确立基准侧的另一侧**（`_crossed_the_axis`，
只看角色自己站在哪；正好在轴线上不算跨线），就在消息后面点名：

```
相机位置违反 180° 轴线规则，可能导致角色左右方向混乱。建议将相机移到轴线另一侧，
或插入中性镜头过渡。（char_001 已经站到轴线的另一侧：这一镜的走位跨线，
只挪机位修不动——请改这一镜的走位或机位角度，或按 §6.2 插入中性镜头过渡）
```

**判据一个字没动**（还是 `Axis.established_side`，还是 error），改的只是
**如实说明根因**：`audit.format_for_llm()` 会把这条消息原样带进修复提示词，
所以模型第一次就能看见"该改走位/角度，而不是挪机位"。

## 守门用例

`tools/blender_tests/test_phase3_audit.py::r001_says_whether_a_character_crossed_the_axis`
——第一镜两人相对而立并让 char_001 走到 **+Y 3 米（跨线）**，第二镜是他的单人镜；
断言 R001 的消息里出现"**另一侧**"且点名 `char_001`。

成对复验：`git worktree add work/verify_r001 b5358e5` ＋ 新用例 → **fail**；
新代码 → 8/8 pass。

## 仍未做（规格裁决）

要不要让**轴线跟着走位重估**（或反过来：走位不许跨线）。两条都会同时动
构建器与规则侧（审计里每镜的轴线必须与摆机位时用的是同一条），所以这一轮
只做"把根因说清楚"，没有动轴线语义。详见 `ACCEPTANCE_STATUS.md` §六十五。
