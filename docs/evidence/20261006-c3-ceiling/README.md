## 这件事的含义（不含"降线"选项）

红线 **E1 ≥ 0.70** 锚定的是"**导演拿到的那 3 条里有几条相关**"（产品自己就是
`rag.cases_top_k: 3`，见 `specs/config.default.yaml:28`）。现在这条读数说明：

* **不是"重排器不够好"**——重排器再好也只能把上限 0.5052 拿满，0.70 拿不到；
* **是"候选池在这个尺子上不够肥"**——平均每条查询只有 **1.67** 条被判相关的候选；
* 因此第三方路线第 3 步（把池子放到 50）**按预注册不需要再做了**（前置的"上限 ≥0.70"没过）。
  这一条**留作下一步的判据**：若哪天重做 C=3 语境、池子肥到 `min-of-3 ≥ 0.70`，再谈 k=50。

**这不是判红线不可达**，而是：**在当前候选池上不可达**。要动的是池子（语料／案例层），
不是把重排器换得更聪明——这两条现在是分开的、可分别证伪的。
