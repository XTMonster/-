## 1. 跑了什么

```
python tools/kb_fetch/build_hypergraph.py --replace-cards work/_replace_cards.txt
  -> {"replace_cards": true, "requested": 52, "matched": 52, "unknown": []}
  -> merge.refresh: {cards: 52, atoms_dropped: 68, atoms_kept: 2762}
```

**52 张**＝那 18 条被判错的边的**全部来源卡**（不止那 17 张孤儿卡）；清洗路径会
**丢掉这些卡的旧原子边、按卡正文重抽**（`run(..., replace_atoms_for=…)`）。
卡片清单 `work/_replace_cards.txt`；重抽前六份产物备份在 `work/_pre_replace_20261008/`。

## 3. 结论：**小幅变好，但把门③ 弄红了 ⇒ 不能直接发货**

门③ 要的是"词表里每个取值都能被某条查询点名"，而点名一个取值的查询必须由一条
**含该取值的边**支撑（门⑨ 要求 `must` 的槽位在 `q` 里出现、门⑩ 要求 `must` 解析得到）
——所以"取值没有载体"这一档在结构上无解。实测重抽之后：

* `雨声` 还有边（`IMPACT_PACK:vfx=smoke,sfx=雨声,movement=固定`）✓；
* **`dolly_zoom`、`尖锐哨音` 一条边都没有了**（它们原来的载体正是被清洗掉的那些边，
  而重抽给那两张卡换成了别的边）。

要走通这条路只有两条：**再抽一次**（＝qwen 第一次会诊点名过的"重新掷骰子"）或
**连词表一起换代**（把这两个真实取值从词表里删掉）。两条都要用户明示 ⇒ **回滚**。

## 4. 两处**我自己的错**，一并记下（都在这一轮里抓到并修掉）

1. **`assertable.json` 是冻结输入，不是派生量**。我一度按"随索引重算"去跑
   `holdout_pool --mechanical`（它给出 `IMPACT 99 / SOUND 30 / MUSIC 46`），
   而这份 oracle 正好按**原**上限做满（`IMPACT 24 / SOUND 11 / MUSIC 21` 对）——
   重算等于**把门④ 的门槛从 24 抬到 30**。回滚脚本因此改成"从 HEAD 逐字节还原"。
2. **补写提示必须标出 `forbid_` 角色**。第一版渲染成 `movement=zoom_in`，
   于是 qwen 把一条"**禁**运镜=zoom_in"的边抄成了"运镜=zoom_in"，那条 spec
   在索引里永远解析不到（门⑩ 红一条）。修好后重问同一张卡即得
   `EMOTION_PACK:emotion=混乱,intensity=high,forbid_movement=zoom_in` ✓。

## 6. 用户点名的「再抽一次」——**做完了，也没成**（掷骰子 #3）

用户 2026-10-07 看到上面 §3 结尾摆出的两条路，选了第一条：
「**再抽一次**（我可以只针对那两张卡重抽——小范围掷骰子，成功则这条路就能发货）」→「**做吧**」。
这一节就是那次掷骰子的读数。结论先说：**这条路也穷尽了**，两个取值一个"没掷中"、一个
"每次都会被重新发明"，而且它俩的病根不是同一处。

### 6.2 两个取值的病根**不是同一处**（这是这一轮最值钱的发现）

* **`dolly_zoom` 是真取值，问题在词表的别名没对上语料的说法。**
  卡 `cine_move_dolly_zoom` 的标题就是**「推拉变焦（眩晕镜头）」**、正文也写着「推拉变焦」，
  而 `tools/kb_fetch/vocabulary.py:124` 给它登记的别名是
  `("移焦眩晕", "希区柯克变焦", "变焦推拉")` —— **`推拉变焦` 四个字一个都没收**（顺序还反着）。
  ⇒ 抽取器要"猜"这四个字对应哪个闭集取值，**猜中与否就是掷骰子**：HEAD 那一版猜中了（1 条边），
  掷骰子 #3 没猜中（0 条边）。所以这不是"这条路的随机性"，这是**一个可以定点修的漏别名**。
* **`尖锐哨音` 是抽取器发明的，掷多少次都会继续发明。**
  它**在 2353 张卡里一个字都没出现过**（上面那把尺子的三行 `0/0/0`），可是它每次都在索引里——
  HEAD 2 条边、掷骰子 #3 1 条边，源卡还都是**卡正文里没有这个词**的卡
  （`gen_edit_0191` + `gen_story_0132`）。而门⑨/门⑩ 要求"点名某个取值的查询必须由一条含该取值的边支撑"
  ⇒ 只要把发明出来的成员摘掉，`尖锐哨音` 就一定落到"没有载体"那一档。**这条不是掷骰子能修的。**

### 6.3 掷骰子本身也是不可复现的（这一轮顺带量到）

两次重抽都从**同一份 HEAD 状态**起步，用的也是同一条命令、同一份 52 张卡清单：

```
python tools/kb_fetch/build_hypergraph.py --replace-cards work/_replace_cards.txt
```

| | 边 | 原子 | 缓存（`cache_stats.after_reroll3.json`） |
|---|---|---|---|
| 掷骰子 #2（23:13，`reroll2.stdout.txt`） | 636 | 2851 | — |
| 掷骰子 #3（23:18，`reroll3.stdout.txt`） | **634** | 2861 | **hit 39 / written 13**（52 张里 13 张每次都要真调用） |

⇒ 这 52 张的重抽**不是可复现操作**，每一次都是一次真掷骰子（这既是"小范围掷骰子"的原意，
也意味着**它不能当验收手段**：同一份输入连跑两次，索引都不是同一个）。

### 6.4 结论：这条路由**穷尽**，剩下的三选一都得用户拍板

1. **就按现状结案**——22 条判决只记不改，索引不动，全部绿灯（代价：门③ 的 `尖锐哨音`
   与"发明取值"这档盲点继续留在库里，并且它已经写进 `docs/evidence/20261007-v15-zerocand-verdict/`）。
2. **只治 `尖锐哨音` 这一档**——把没有真载体的取值从**词表**里去掉（＝词表换代），
   或接受门③ 的一条已知盲点。修 `dolly_zoom` 那一半可以顺带做：给
   `tools/kb_fetch/vocabulary.py:124` 补上语料真实用词 `推拉变焦`（这是**加别名、不是放宽判据**，
   但它同样是冻结输入 → 仍属换代）。
3. **治根**——改抽取提示：成员必须给出**正文原句**或**取值本身/同义词**才能落地
   （现在 `gate/v2` 只对 `forbid` 成员查宿主，见 `_reroll.out` 里的 `unsupported_prohibition_host`
   拦掉了 15 条），然后整库重抽。成本最大，但这是唯一能真正消灭"发明取值"的一刀。
