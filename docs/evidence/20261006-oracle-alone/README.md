## 三种呈现方式，同一批 64 条查询的 oracle-3

| 呈现方式 | E1（两位评委均值 ≥4） |
|---|---|
| "完美重排上限"（**数标签**：池子里有多少行在**各自原三元组**里被标过相关） | **0.8438** |
| oracle-3 当成**一个新的三元组**重新盲评（`…-fresh-oracle/`） | **0.4583** |
| **oracle-3 逐条单独盲评**（本目录） | **0.1458**（28/192） |

## 这条读数推翻了什么

`docs/knowledge/DECISION_BRIEF_RK13.md` 里记着第三方（GPT-6A）的方案 **B**：
"**固定呈现方式、逐条独立盲评**"，理由是"同案因陪衬变化而跨过 4 分 ⇒ 说明混入了批次效应"。

**实测是反的**：逐条独立判 **比三元组还严**（0.1458 < 0.4583）。
⇒ **B 这一形式不能把读数救回来，反而把它压得更低。**

## 真正的机制（三步合起来看）

| 观察 | 值 | 结论 |
|---|---|---|
| 随机抽样的 60 条案例："单独判 vs 原三元组"标签翻转 | **~7%**（8/118，方向单一） | 语境效应**存在但小** |
| oracle-3（**最高分的那批**）在新三元组里 | 0.8438 → **0.4583** | 换陪衬对**高分案例**影响极大 |
| oracle-3 **单独**判 | **0.1458** | **独自呈现是最严的语境** |

⇒ 评委给分**强烈依赖同批呈现**（同一批案例：跟原来的伙伴 0.84、跟另外两个强的 0.46、单独 0.15）。
**"3 条里几条相关"不是案例的稳定属性，而是"案例 × 呈现方式"的属性。**
