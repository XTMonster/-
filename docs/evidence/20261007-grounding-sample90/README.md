# 出处缺口：裁定要的**分层抽检 90 槽位**（样本＋机械预读＋三分类作业）

日期 2026-10-07 03:0x。依据：`../20261007-grounding-ruling/README.md` §1 第③条——
"从 1,262 条未佐证槽位**分层抽 90 条**（三 pack 各 20 ＋ 其余 kind 30）人工三分类
（**蕴含未写出／挂错卡／取错值**）；后两类 ≤10% ⇒ '修数据'被证伪；≥33% ⇒ '暂缓重抽'被证伪"。

## 一、抽样框（**互不重叠**、可复现）

* 样本总量 **90**：`closed_loop_kind 30`（`headroom_policy`／`composition_rule`／`camera_angle`，
  它们的未佐证槽位共 **292** 个）＋ `pack:PERFORMANCE_PACK 20` ＋ `pack:SHOT_PATTERN 20` ＋
  `pack:STAGING_PACK 20`。
* **抽样规则确定可复现**：先给闭环三 kind 留 30 个名额，其余按 `(edge_id, kind, value)` 排序后
  每层取前 20（**不是随机**，写明即可复算）；行内带 `stratum` 字段，**一条不会被数两次**。
* 逐条证据与"卡正文节选"用**与判据同一份文本**（`attestation.card_blob`）⇒ 分类者看到的
  就是判据在比的那段字。

生成器：`work/_sample_grounding90.py`（本目录留档 `sample_grounding90.py`）。

## 二、**机械预读**（不是分类结论）

| 量 | 值 |
|---|---|
| `surface_in_card` | **0**（按构造必然为 0——样本全部取自"未佐证"） |
| `topic_mismatch`（来源卡有 `topic`，且 ≠ 成员 kind） | **88 / 90** |
| `topic_ok_or_unknown` | 2 / 90 |

⇒ 机械信号非常强（97.8% 的样本，其来源卡的 `topic` 与成员 kind 不是一回事）。
**但它只是机械信号**：`topic` 字段本身也是生成物，它错这条判据就跟着错。
真正的三分类由裁定通道来做（见下）。

## 三、三分类作业（**正在跑**，产品落本目录）

`work/_run_grounding_batches.py`：把 90 条切成 **12 批 × 8 条**（每批约 4–5.5 KB），
**串行**调用裁定通道（`--level high`，守它的思考预算），逐批落
`batch<N>/测试与验收.json`。

* **为什么不用 `.ps1` 驱动**：中文角色名经 **PowerShell 5.1** 的命令行会被按 ANSI/GBK 解码——
  实测第一版脚本第一轮就报"未知角色 `娴嬭瘯涓庨獙鏀?`"（本仓已经踩过两次：`.ps1` 必须 ASCII-only；
  中文别走那个命令行边界）。改成 Python 进程内传参后就正常了。
* 判词一律记 `reviewed_by` 通道名，**绝不写 `human`**；每批自带 usage。

## 四、未验证 / 边界

1. **三分类还没出结果**（12 批在跑）；本目录现在只有抽样与机械预读。
2. `topic` 字段的**准确率没核**（机械预读的已知弱点）。
3. 样本是**确定性取前 N**，不是随机抽样——按裁定的话说，它给的是"**分层覆盖**"，
   不是"置信区间"。要更强的结论得换随机种子或加大样本。
