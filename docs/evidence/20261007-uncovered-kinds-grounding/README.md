# 剩下那三个"未纳入"的 kind：缺的**不是区间**，是**成员值得有出处**

日期 2026-10-07 02:2x。工具：`work/_peek_uncovered_rules.py`（只读）。

## 一、先把三个 kind 摊开（索引实测）

| kind | 成员数 | 取值分布 |
|---|---|---|
| `headroom_policy` | 83 | `cinematic 78`／`board 5` |
| `composition_rule` | 77 | `framing 20`／`balance 21`／`occlusion 12`／`lead_room 11`／`rule_of_thirds 8`／`headroom 5` |
| `camera_angle` | 175 | `平视 113`／`高机位 22`／`低机位 20`／`过肩 12`／`荷兰角 6`／`骑轴 2` |

三者**不是同一种问题**：`headroom_policy` 是**策略名**（产品侧有 `framing.headroom_policy`）、
`composition_rule` 是**规则名**（产品侧是 `composition_score` ＋阈值 70）、
`camera_angle` 是**几何分类**（得由机位与主体反推）。所以"给它们定个区间"这个说法本身就不成立。

## 二、抽查两张来源卡：**成员的取值根本没写在卡里**

| 边上的取值 | 来源卡 | 卡的实际内容（原文节选） |
|---|---|---|
| `composition_rule:balance` | `gen_cine_0258` | "**三脚架顶须调水平**：架设三脚架时，先通过伸缩各腿适应地面高低差，把三脚架顶面调至水平……" |
| `camera_angle:平视` | `gen_perf_0525` | "**迟缓如蜗牛的肢体动作**：表现伪善或压抑的角色时，肢体动作应像大蛞蝓或蜗牛……" |

⇒ 这两张卡**一个字都没提**"构图平衡"或"平视机位"。也就是说：这两个成员取值**不是从来源卡推出来的**。

## 三、这不是抽样偏差：链上一直在报同一个数

链的 `knowledge_attestation.json`（**每次全链都会写**）报的是：

```
attestation (diagnostic): 0.2078 of checkable member slots are named by the edge's own source cards
（638 条边里只有 38 条**完全**被自己的来源卡佐证）
```

⇒ **约 79% 的成员槽位，其取值在来源卡里找不到**。上面两张卡只是这 79% 里的两个样本。

## 四、结论与下一步（不自己编判据）

* 对这三个 kind，按裁决 F2 的第一条动作——"**区间必须逐字引自规则原文**"——**在这里无路可走**：
  原文里既没有区间，也**没有那个取值本身**。若照 F2 的第二条"原文无区间者先改知识侧"，
  要改的也不是"补个区间"，而是**让成员值有出处**（抽取/归属层面的问题）。
* 因此**本轮不动它们**：不给阈值、不给映射、不写默认值。**如实记成"未纳入"**，
  并把"**成员值得有出处**"这件事**提交裁定**（它影响的是整张索引，不只是这三个 kind）。
* 影响面先说清：这条与 `fixtures/closure_uncovered_kinds.json` 里那三个 `B` 类条目**同一个根**——
  它们的 `data_source` 我此前写的是 `derivable-from-*`，现在按实测应读作
  "**取值本身未被来源佐证**，谈不上可推"。
