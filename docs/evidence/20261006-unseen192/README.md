# 192 条**未见查询**上的三方对照：LLM 重排仍是最好，微调重排器**跨项目泛化不住**

日期 2026-10-06 09:06。触发：GPT-6A 会诊的验收判据要求"另取 100 个未见分镜"，
而原冻结查询集只有 **64** 条（来自一个项目）。

## 查询集怎么来的（可复算）

```powershell
python tools/knowledge/collect_shot_prompts.py --roots docs/evidence --out work/eval_sets/shot_prompts.pool.txt
# 28 个项目 -> 去重后 1,315 条；**排除 20261006-long21**（微调训练集那一份）-> 1,251 条
python -m tools.knowledge.freeze_eval --queries work/eval_sets/shot_prompts.unseen.pool.txt `
    --out work/eval_sets/unseen192/queries.txt --size 192 --seed 20261006
```

* 池＝**已入库真实运行**的逐镜散文（`scenes[].shots[].prompt`），**跨项目去重**
  （`chunked_long*` 是同一脚本的多次分块跑，不去重"未见"就是假的）；
* 冻结 **192 条**（`freeze_eval` 是本仓冻结集的唯一入口；`file_sha256=` 见
  `work/eval_sets/unseen192/heldout.manifest.json`）。
* ⇒ 对**微调过的重排器**来说，这 192 条是**真正没见过**的（既不是它的训练查询，
  也不是同一个项目）。

## 三方对照（同一批 192 条，官方口径＝两位评委均值 ≥4）

| 方法 | 官方 E1 | 只 deepseek 评委 | 只 glm 评委 |
|---|---|---|---|
| 不重排（前 3 条） | **0.2031**（117/576） | 0.1933 | 0.3734 |
| **微调 cross-encoder** | **0.2483**（143/576） | 0.2209 | 0.5220 |
| **LLM 重排（`select`＋线索）** | **0.3958**（228/576） | 0.4073 | 0.6218 |

## 结论（照实说，两句）

1. **微调重排器确实有用，但只在"同域"里**：它在 16 条**同项目**留出查询上是 0.3542、
   代理口径 0.5625；**换到别的项目就掉到 0.2483**（只比不重排的 0.2031 高一点）。
   ⇒ 它**过拟合了训练域**（`20261006-long21` 那个场景/人物），**跨项目泛化不住**。
2. **LLM 重排（0.3958）仍是目前最好的**，而且**跨项目也稳**（64 条上是 0.44、192 条上是 0.40）。

**顺带把两种噪声都压小了**：192 条（576 行）比 64 条（192 行）把"赢/没赢"的分辨率提了 3 倍，
而这次的排序（LLM ＞ 微调 ＞ 不重排）与 64 条那次一致 ⇒ **这个排序是稳的，不是噪声**。

## 仍未解决（如实挂）

* **都没有到 0.70**：最好的 0.3958 离红线还差 0.30；而**完美重排上限**在同一批池子上是
  ~0.84（此前在 C=3 口径下测过）。
* 微调那一版只训了 16 条查询域内的数据、2 epoch ⇒ **要救它得先解决"训练数据的域覆盖"**
  （拿 1,251 条池子上的标签去训，而不是只用 long21 那一份的 288 条查询）。
* 训练标签仍来自**同批差 0.27** 的两位评委（P2）——它学到的就是那两位的平均口味。
