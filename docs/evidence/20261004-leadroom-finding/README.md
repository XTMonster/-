# 一次**负结果**加一个真缺陷：视线留白、朝向镜像、以及"机位瞄准的是起始站位"

三份 `composition_*.json` 是同一份工程（`docs/evidence/20261003_chunked_long9/project`）
用同一支探针（`work/_axis_rebuild_probe.py`，零 LLM）重建后逐镜复评的原始产物。

| 产物 | 树 | 构图分中位 | 构图门 ≥70 |
|---|---|---|---|
| `composition_before.json` | `9aa7190`（本轮改动前） | **64.7** | 19 |
| `composition_with_offset.json` | 加了"视线留白横移 1/6 幅宽" | 55.8 | 21 |
| `composition_facing_fix_only.json` | 只修朝向镜像、不留白横移 | 63.8 | 20 |

## 1. 先说负结果：**"让求解器遵守 §10.4"这一步不能直接开**

做法：单主体镜头的对准点朝视线方向横移 1/6 幅宽（主体落到背向视线的那条
三分线上）。在**孤立几何**上它是有效的——`work/_leadroom_probe.py` 实测同一机位下
`lead_room` 0.286 → 0.769、`rule_of_thirds` 0.208 → 0.680、总分 73.2 → 89.9。

但在**真实工程**上重建复评是净负：构图分中位 64.7 → 55.8，**25 镜降 / 16 镜升**，
掉得最狠的 −48.1 / −44.0 / −39.8 三镜全部是**主体本来就不在画面中心**的镜头
（`framing` 从 0.81 直接塌到 0.0，`balance` 本来就是 0.0）。

所以：机制（`cinema/station.aim_offset_for_lead_room` ＋
`solve_framing(aim_offset_x=…)`）保留并有用例（`tests/test_lead_room_aim.py`），
**但构建器这一轮不启用它**，理由写在 `layer3_engine/shot_builder.place_shot_camera`
的注释里，指回本文件。

## 2. 为什么那些镜头本来就不在中心：**机位瞄准的是"起始站位"**

`work/_anchor_probe.py`（同一份 `long9` 工程，零 LLM）逐镜对比
"机位用的锚点（`CastMember.initial_location`）"与"角色在该镜首帧的**实际**位置"：

```
shots = 64
单主体且与起始站位差 > 1 m 的镜头 = 20
最远：shot_059 伊恩 实际 (8.6, -6.0) ／ 锚点 (0.9, 0.0)  → 差 7.7 m
      shot_062 米迦尔 实际 (-4.82, 0.42) ／ 锚点 (-0.9, 0.0) → 差 3.92 m
      shot_020/023/025/028/031/… 米迦尔 实际 (-4.11, 0.11) ／ 锚点 (-0.9, 0.0) → 差 3.21 m
```

角色在前面镜头里走动过，而机位仍然按"剧本开始时的站位"摆：这些镜头本来就
把主体拍在画框边缘或画外。**这是剩下的 COMPOSITION 低分的主要来源，
也解释了负结果**——在边缘的构图上再加 1/6 幅宽横移，只能把主体推出画外。

下一步（尚未做）：把机位锚点从"起始站位"改成"该镜首帧的实际位置"。
`build_scene` 现在的顺序是"逐镜摆机位 → 收集动作 → 烘焙动作"，所以要么两趟
（先烘焙、后摆机位），要么先按纯运动模型推算出各镜首帧位置。**这是下一刀。**

## 3. 顺带修掉的真缺陷：**朝向被镜像**

`cinema_engine/composition_guide._screen_facing` 从 yaw 回读世界朝向时写的是
`(sin θ, cos θ)`，而 `utils/geometry.facing_to_rotation_z` 的逆是
`(-sin θ, cos θ)`（该文件的 docstring 早就把这条镜像标成 v1.3 修过的历史缺陷）。
少了那个负号 ⇒ **声明面朝 +X 的角色在评分模型眼里面朝 −X**，于是
`lead_room` 奖励**错的**那一侧。`work/_leadroom_probe.py` 的直接对照：

```
同一机位、声明 facing=(1,0,0)：
  修前  screen_facing=-1（认为朝画面左）→ 把主体放到**正确**的右侧留白三分线 ⇒ lead_room 0.0
  修后  screen_facing=+1（确实朝画面右）→ 同一位置 ⇒ lead_room 0.769
```

修法：改用 `utils/geometry.rotation_z_to_facing`（单一真源），不再自己重推一遍。
效果（`long9` 重建）：构图分中位 64.7 → 63.8、构图门 19 → 20 ——**总量几乎不动**，
因为它修的是"分数与真实朝向的对应关系"，不是把分数做高：修前那两项对真实朝向
是随机的，修后才第一次量与所见一致。**这是后续所有朝向相关工作（留白、反打、
屏幕方向连续性）的前提。**
