## 1. 它为什么存在（S0 的谓词 ②）

`docs/knowledge/PLAN_HYPERGRAPH_v3.md` 的 S0 写着：基线命令 ＋ 种子写进证据目录，
**两条命令各跑一次并入库**。原因是 §九十七 留下的那条候选（ADR-0014 的 ② 魔改：
词法适配器）**每臂只有一次读数**，而 E1 的分子是**两个 LLM 评委的 1–5 分取均值 ≥ 4.0**
（`tools/knowledge/e1_panel.py:50` `DEFAULT_PANEL`、`:52` `RELEVANT`）——判分本身随机，
一次读数分不出「检索变好了」与「这次评委给分松」。

## 2. 怎么复跑（命令逐字；判分**没有种子**，这是重复测量的原因）

```powershell
$env:GLM_TIMEOUT = '420'          # glm-5.3 是始终思考模型，单次判分是分钟级
python tools/knowledge/e1_panel.py `
    --project docs/evidence/20261006-long21/project/project.bdproj `
    --cases-dir knowledge --out <out>.jsonl --top-k 3 --workers 3 `
    --adapter none               # 产品现行的 hybrid；另一臂换成 --adapter lexical
```

* 查询集：long21 那份真跑的 **64 镜**，`top_k=3` ⇒ 每臂每轮 **192 行**判分；
* 面板：`deepseek-chat` ＋ `glm-5.3`（两族），阈值 4.0；
* 两臂跑在**同一份发货索引**上：`cases_fingerprint = 48df4a53c2c9…`、
  `cases_digest = 937a04e052e67548…`（四份产物逐字相同，见 `baselines.json`）；
* 每行自带 `retrieval_path`，所以一份证据里两条路不会混账；
* `work/_baseline_repeats.ps1`（草稿区）是当次的实际驱动脚本，`runs.log` 是它的输出。

## 3. 读数

| 臂 | rep1 | rep2 | 均值 | 极差 |
|---|---|---|---|---|
| `hybrid`（产品现行 BM25） | 39/192 = 0.2031 | 39/192 = 0.2031 | **0.2031** | **0.0000** |
| `lexical`（ADR-0014 ② 候选） | 37/192 = 0.1927 | 44/192 = 0.2292 | **0.2109** | **0.0365** |

* **Δ（lexical − hybrid）＝ +0.0078**，而同臂重复的极差最大到 **0.0365**
  ⇒ 机器可判的结论 `separation_measured = false`（`baselines.json`）。
* **跨重复翻判的行**（同一份候选集、同一个面板、只重判一次）：
  `hybrid` **12/192 ＝ 6.25%**、`lexical` **11/192 ＝ 5.73%**
  （`baselines.json` 的 `verdict_flips`；键是 `(查询, 案例)` 那一行，
  不是 `case_id`——同一个案例会被多张镜头召回，定位要到行）。
  ⇒ 这不是"个别抖动"：**每十六行就有一行**会因为评委重判而翻转，
  而两臂的整臂差只有 0.0078（＝1.5 行）。

### 3.1 这就是 §6(b) 要的**评委噪声**（第一半）

`work/_critique_v4_1.md` §6(b) 要求把方差拆开：固定候选集只重跑评委 / 固定评委只重跑
检索。**第一半本批顺带就量到了**——两臂的两次重复喂给评委的是**逐行相同的候选集**
（检索是确定性的；`baselines.json` 里那次"键集必须相等"的断言就是它的机器证据），
所以下面的散布**只可能**来自判分：

| 臂 | 分数动过的行 | 平均 \|Δ分\| | 最大 \|Δ分\| | 翻判行 | 翻判率 |
|---|---|---|---|---|---|
| `hybrid` | 68/192 = 35.4% | **0.190** | 1.0 | 12 | 6.25% |
| `lexical` | 59/192 = 30.7% | **0.167** | 1.5 | 11 | 5.73% |

分数是 1–5 的两个评委均分。把三件事并排看：**单行平均位移 0.178 分**、
**每 16 行翻 1 行**、**整臂差只有 0.0078（1.5 行）**。
⇒ "哪条路更好"在这个样本量上被噪声盖住了；第二半（固定评委只重跑检索）**未做**。

## 4. 这一批**推翻**了什么（如实记，不修饰）

1. **§九十七 的那条 Δ 不成立**：它记的是 `hybrid 0.1823 → lexical 0.2135`（+0.0312）。
   今天同一份索引、同一批查询上，`hybrid` 的重跑读数是 **0.2031**——**连"旧基线"本身
   都没复现**（35/192 → 39/192）。方向也不稳：旧读数说 lexical > hybrid，
   今天两次重复里 lexical 先低（0.1927 < 0.2031）后高（0.2292 > 0.2031）。
2. **绝对差 0.0078 < 极差 0.0365** ⇒ 在这个样本量上，"启用词法适配器能提高 E1"
   **没有证据**。ADR-0014 ② 那条候选因此停在"候选"是**对的**，不是保守。
3. **台账 §九十二／§九十七 引的"噪声底 ±0.008"量级不符**：那是一次**同臂**
   重复的散布；这里的同臂极差是 0.0365（lexical）、0.0000（hybrid）。
   两臂的散布**不同量级**，所以"±0.008"不能当通用噪声底用。

## 5. 边界（不许含糊）

* **每臂 2 次**（N=2）。`work/_critique_v4_1.md` §6 要求 N ≥ 3 ＋ 报告均值 ± 极差；
  本批只做到 N=2，**差的这一次如实挂着**，未补之前它不构成"重复够多"的证据。
* 判定只覆盖 **192 行 / 64 镜 × top-3**。判据、门限（0.70）、oracle、`SCORE_WEIGHTS`
  一个字没动；`E1` 仍判 fail（0.2031 与 0.2109 都远低于 0.70），`RK-13` 仍 failed。
* 本批**没有**做方差分解（固定候选集只重跑评委 vs 固定评委只重跑检索）——
  那是 §6 的另一条要求，也挂着。
* 判分**没有种子**：`e1_panel.py` 调的是厂商默认温度，所以"同一臂重复"不是
  "同一随机流重复"，这也是本批必须看极差、而不是看单次读数的原因。
