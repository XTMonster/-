# 问：这条质量度量本身可信吗？最该被推翻的假设是哪条？

## 背景（一个 Blender 白模预演插件的知识栈验收）
- 知识栈给导演每一镜返回 **3 条参考案例**；验收有一条红线 **RK-13：E1 >= 0.70**。
- **E1 定义**：交给导演的那 3 条案例里，有几条被判"相关"。判法：两位 LLM 评委各打 1-5 分，
  **取均值 >=4 记相关**；E1 = 相关条数 / 面板总条数。判据/阈值/分母全部冻结，agent 不许改。
- 实测事实（均有入库证据、可复算）：
  1. 把每条查询"标签分最高的 3 条"（即 oracle 三元组）**重新盲评**，E1 只有 **0.4583**。
     另一常见"完美重排上限"公式（数池里有多少行在原三元组里被标过相关）给 0.8438。
  2. 候选面从 50 挖到 120，可达值只从 0.4583 -> 0.4740（+0.016）；而"数出来的上限"升到 0.9688。
  3. 让大模型读 50 条候选挑 3 条：**六种提示词形状**全试过，见顶 0.41-0.46（最好 0.44）。
     训一个 cross-encoder：192 条未见查询上只有 0.2483，且过拟合训练域。
  4. 同一条案例"单独判 vs 在原三元组里判"的标签翻转率约 7%，方向单一（三元组抬高相关性）。
  5. 同一条命令重跑两次，约 30% 的行分数会变（评委本身不稳）。
  6. 把 oracle-3 **逐条单独盲评**：E1 掉到 **0.1458**（比三元组 0.4583 更差）。

## 请你回答（<=400 字，分点、可证伪）
1. E1 这条度量把"**案例相关性**"和"**同批呈现方式**"混在一起了——这个判断成立吗？依据是什么？
2. 若成立，**不动 0.70 这个阈值**、也不偷偷换尺子的前提下，怎样把度量改成可结算的（给出具体定义式）？
