
## 判定：**0.70 在产品口径上可达**

红线 E1 ≥ 0.70 等价于"64 条查询里 **≥45 条**能拿到 ≥3 条相关"（45/64 ＝ 0.703）。
挖到 50 之后是 **46 条**、上限 **0.8438** ⇒ **过线**。

| 判据（第三方原话，按其**意图**修正到产品口径） | 要求 | 实测（C=3） | 判定 |
|---|---|---|---|
| ≥3 相关查询数 | 从 24–25 抬到 **≥45** | **46** | ✓ |
| 完美重排上限 | **≥0.70** | **0.8438** | ✓ |

**为什么这不是"降线"**：红线、阈值（4.0）、分母、判分语境（C=3，＝产品自己
`rag.cases_top_k: 3`）**一个字都没动**；变的只是**检索取多深**——而"取多深再重排到 3"
本来就是 retrieve-then-rerank 的标准形状，产品对用户**仍然只返回 3 条**。

## 还差什么（这是新的、可执行的下一步）

上限＝**完美重排器**的分数，而**实测的重排器**离它还很远：

| 量 | 值 |
|---|---|
| k=50、**不重排**的 E1（＝前 3 条） | **0.2188** |
| k=50 的完美重排上限 | 0.8438 |
| 已测的最好重排器（Kimi，k=20→3，**已因余额停用**） | 中位 0.3073（该池上限 0.5052 的 61%） |

⇒ 要过线，**重排器得把 0.2188 抬到 0.70 以上**，也就是拿到该池上限的 **83%**。
已测的最好重排器只拿到 61%（而且那还是在更浅的池子上）。

**重排通道现在受用户 2026-10-06 的规则限制**："gpt6A 只能用于人工裁决和执行计划书写，
其他的用 glm 和 DeepSeek"；Kimi 又因余额被挂起 ⇒ 重排只能用 **GLM／DeepSeek**，
而这两个族**同时是 E1 的评委** ⇒ 它们的重排读数带**同族自证**的折扣（要在证据里写明）。

## 未验证 / 风险

  两跑极差 0.0104／≥3 查询数极差 1），过线的那 1 条余量不大 ⇒ **要引用"过线"就该补一跑**。
* 挖更深（k=100）会不会继续涨：**未测**。
