## 已经据此修掉的三处（见 commit `e7182da` / `dc7fd0a` / `2d57eb4`）

1. `repair_applied` 的判据从"任何成功的工具调用"改成"**改动类**工具"
   （`contracts/tools.py::MUTATING_TOOLS`，只读工具不算动手）。
2. `camera.side` 收成闭集（`cinema/framing.py::CAMERA_SIDES`）；此前草案 schema 是裸
   string、求解器对未知取值**静默折成 `front`**——模型写的整句中文全成了正面机位。
3. 修复提示词按问题分类点名工具：时间轴类（R003/R011）**必须重新提交这一镜的草案**
   （`emit_shot_draft` 会整份替换计划的动作表），空间类才用场景工具。

**如实记账**：③ 在下一跑（`20261003_chunked_long5`）里**没有**让 churn 下降——
模型仍然只调只读工具。这条是"提示词改了但行为没变"的负结果，记在这里。

## 还没解决、需要设计决策的

* **修复回合为什么不动手**：B4 按 §7.1 是"一次 `tool_choice=required`"（模型必须动手），
  实测它只做只读检查；B5（多步、`auto`）里**会**动手（`setup_camera`），但那时
  B4 的两次额度已经烧完。可选：B4 的一轮若"没有任何改动"就**直接升级 B5**（省一次调用、
  早一点进"边看边调"），或让 B4 的第二轮带上上一轮的观察。两者都改循环形状。
* **构图模型与求解器是否对得上**：求解器摆位、构图模型打分，两者都在这条链上；
  得分结构（三分线交点 0.15、视线留白 0.20）在真实运动镜头上几乎拿不到满分。
* **保存的项目过不了 SDL 校验**：这一跑的 `project.bdproj` 在 `load_project` 里被判
  `S6 装不下对白`（多镜）——即"改一镜重出一镜"这条工作流对**真实运行**是断的。
