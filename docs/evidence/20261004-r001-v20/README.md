# P14-76：会诊 ① 的"用真机位重算轴侧"——**实测后回退**（第三次负结果，如实记）

会诊（`docs/evidence/20261004-glm-consult-v19a2/`）给的最小形状是：给
`crossing_events` / `axis_state` 加可选 `cameras`，`flip` 改成"机位相对 A→B 连线的
叉积符号在镜内变号"；并**第 5 步**要求"规则侧在相机建好后用真机位重调、与构建器
用过的侧表 diff"。前一半**落地了**（纯函数、带行号证据；6 条守门在
`tests/test_axis_crossing_events.py`）。后一半**试过、实测不利、回退**——这一页就是
证据。

## 试了什么

`rule_checker._axis_sides()` 改成读**真机位**重算的表（每镜取切入点机位），
`_camera_on_wrong_side` 就按它判；构建器仍按计划期近似摆机位。

三份冻结工程、同一支零 LLM 复评器（`work/_reaudit_probe.py`）：

| 工程 | 逐镜通过（判据按近似 → 按真机位） | R001（近似 → 真机位） |
|---|---|---|
| long9 | 28 → **24** | 13 → **33** |
| long11 | 9 → **7** | 40 → **43** |
| long12 | 24 → **24** | 7 → **7** |

`long9` 一次多出 **20 条** R001。逐镜数据：`exact_table_*.json`（实验）、
`baseline_*.json`（回退后）。

## 为什么判它**不是**更准的判据（关键证据）

拿一条**独立**的判据投票：`_screen_polarity_flip`——把两人投影到屏幕、看相邻两人镜
的**画面左右序**有没有在没人看见时翻转（它不读轴侧表、也不读叉积符号）。逐镜数据在
`bridging_*.json`：

| 工程 | 真机位表比近似表多报"机位在错侧" | 其中被画面左右序**证实**的 |
|---|---|---|
| long9 | **29** | **2** |
| long11 | 3 | 0 |
| long12 | 0 | 0 |

`long9` 的 29 条里只有 2 条在画面上看得见——**其余 27 条是自指回路**：
机位本来就是照计划期近似摆的，再拿机位去决定"换位看不看得见"、又用同一张表回过头
判机位；固定点不保证收敛（会诊自己在 F1 的 `not_checked` 里也点了这一层）。

## 落地了什么、回了什么

**留下**（纯层，与规则无关）：

* `cinema/axis.camera_side_of`（与 `Axis.side_of` 同一约定，1 条守门）；
* `crossing_events(..., cameras=None)` / `axis_state(..., cameras=None)`：给机位就按
  叉积符号判 `flip`，不给就退回计划期近似；6 条守门，含会诊给的**两个反例**
  （转 **100°** 但没扫过机位 ⇒ 不该翻；只转 **50°** 但扫过机位 ⇒ 该翻——旧判据两条
  都判反）。

**回退**：`_axis_sides` 仍返回构建器那张表（规则与构建器继续共用同一份，v1.9 的
`long9` 13／`long11` 40／`long12` 7 一字不动）。

**改为诊断**：`_axis_state_divergence` 在两张表分歧时**只报第一处**并给出总数
（`long9` 38 镜、`long11` 3 镜、`long12` 0 镜）——分歧本身是"构建器的近似该升级了"
的信号，逐镜报会把修复回路淹掉。

## 下一刀（写给接手的人）

分歧的**根因在构建器**：它在没有机位的阶段就得决定从哪一侧摆机位。要消掉这 38 镜，
需要"建机位 → 用真机位重算 → 有分歧再重建"的**两遍法**，而那是个固定点问题
（会诊原话："固定点不保证收敛，远超最小改动"）。在收敛性有结论之前，把规则换成
真机位表只会把 27 条画面上看不见的分歧变成错误。
