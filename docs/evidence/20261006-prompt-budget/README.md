# 包线能不能加到"四五万字符"？——**实测说不**，但"一刀切"确实错了（已改成按通道）

日期 2026-10-06 21:2x。用户问："**字符不能加到四五万么？或者自适应**"。
本目录把这个问题落回**实测包线**，并把"一刀切 3,000"改成**按通道**。

## 一、先把"能不能"答清楚：**四五万没有实测支持**

| 通道 | 实测 | 结论 |
|---|---|---|
| `glm-5.3` | 5164 token 的输入（≈7600 字符）在 `low` 档把 32768 个 completion token 全烧在 reasoning（32532）、`finish_reason=length`、**正文为空**、白等 460 s | 安全区 **≈3,000 字符** |
| `relay`（`gpt-6-astra`） | **5,309 B** 的包 **6 分钟内**返回正文（`docs/evidence/20261006-gpt6a-round2/`） | ≥5.3 KB **可以** |
| `relay`（`gpt-6-astra`） | **17.5 KB** 的包 **64 分钟零输出**；~6k token 的包同样 64 分钟零输出（`docs/evidence/20261006-gpt6a-consult-liveness/`） | **远小于 17.5 KB** |

⇒ **实测的"死亡点"在 17.5 KB**，而"可用点"在 5.3 KB。**40–50 KB 是死亡点的 2.3–2.9 倍**，
没有任何一次实测支持它；按现有规律（生成时间随输入膨胀），它会比 17.5 KB 那次更糟。
**所以不能靠"把常数改大"拿到它。**

## 二、但"一刀切 3,000"确实是错的——**已改成按通道**

那 3,000 是 **GLM-5.3** 那一档的实测安全区，却被当成所有通道的预算——
于是中转站上白扔了实测出来的余量（我先前那次"压到 2,016 字符"就是这个错配逼出来的）。

`tools/plan_writer.py` 现在：

```python
DEFAULT_MAX_PROMPT_CHARS_BY_PROVIDER = {"glm": 3000, "relay": 6000}

def default_max_prompt_chars(provider):   # 未知通道取最保守那一档，不猜
    ...
```

* **`--max-prompt-chars` 不填 = 按通道自动**（`--provider relay` 得 6000、`glm` 得 3000）；
  显式给数仍然覆盖；`0` 仍是"不限"。
* 中转站取 **6,000**：比**实测可用**的 5,309 B 留一点余量，又离**实测死亡**的 17.5 KB 有 **2.9×** 安全距离。

**实测验证（不是"参数传对了"）**：同一个 9,046 字符的包——

```
--provider relay（不填预算） ⇒ 拒绝：超过预算 6000
--provider glm  （不填预算） ⇒ 拒绝：超过预算 3000
```

守门：`tests/test_plan_writer.py::test_the_prompt_budget_is_per_channel_and_grounded_in_measurements`
（断言 relay > glm、relay ≥ 5,309、relay ≤ 17,500/2、未知通道取最保守）。全量 **2381 passed / 1 skipped**。

## 三、"自适应"真正的含义（以及它现在到哪一步）

* **已做**：预算**按通道**取，且数字**写在实测表旁边**（不是散在文档里的民间传说）。
* **要往上抬的唯一正当办法**：**实测包线扫描**——拿 6 KB / 9 KB / 12 KB / 15 KB 四个尺寸的包各发一次，
  记"是否返回、多久、finish_reason"，然后把预算钉在**最大的实测可用点**上。
  **这一条本轮没做**（通道上正跑着两个任务），**可随时做**。
* **不做**：超预算时**静默截断**——那是降级（会悄悄丢内容）；现在的行为是**拒绝并给调法**。

## 四、未验证 / 边界（如实挂）

* 预算比的是 `gc.compose_user_message(...)`（**用户消息**，即"可变的那个包"），
  **不是**"system 契约 ＋ 用户消息"的全文——契约是工具常量（~5 KB），不随问题变。
  所以数字与实测表的可比性成立（实测那几个包也是按"问题正文"量的）。
* **正在跑的那个重规划包**（`work/_plan_replan/`）全文 8,064 字符（含契约）、用户消息 ≤6,000，
  落在 **5.3 KB–17.5 KB 之间的未测带**上——**它能不能在合理时间内返回，本身就是一次抽样**。
* 只统计了**两个通道**；没有扫过尺寸曲线。
