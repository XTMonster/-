# R3 的"完美重排上限"**不可复现**：同一命令两次跑给出 0.7760 ↔ 0.7188

日期 2026-10-06。本目录是**审计发现**，不是新读数——它把 `docs/evidence/20261006-e1-ceiling/`
那份"结构可达"证书放进重复跑的尺子里量了一次。


⇒ 上限 **0.7760 ↔ 0.7188（极差 0.0573）**、≥3 相关查询数 **38 ↔ 32（极差 6）**、
而 E1@前 3 行 **0.2812 ↔ 0.2708（极差 0.0104，在 0.02 噪声带内）**。

## 根因（已量到行级）

两次跑的**候选面逐字相同**（64/64 条查询的 top-20 顺序一致——BM25 确定性），
差异**全部**来自评委：**1,280 行里 385 行（30.1%）评分不同**，
差值分布 `{-0.5:176, +0.5:189, -1.0:12, +1.0:7, +1.5:1}`——一次"某位评委差一分"。

于是 **8 条查询在"≥3 相关"与"不足 3"之间跳变**（7 条 yes→no、1 条 no→yes，净 −6）。

**为什么上限比 E1 敏感**：E1@3 是"前 3 行里相关几条 / 3"，多数查询两头都稳；
上限却是 `mean(min(3, 相关行数)/3)`——**每条查询的值非 1 即 <1**，一条查询翻一下就是 1/64＝0.0156。
0.0573 ＝ 3～4 条查询的跳变，正是这个机制。

## 它改了什么（口径，不改判据）

* **判据一个字没动**：相关仍是"两位评委 1–5 分取均值 ≥ 4.0"，红线仍是 E1 ≥ 0.70，
  分母仍是面板条目数。变的只是**"上限"这个派生量必须报极差、不许报单点**。
* R3 台账里"完美重排上限 ＝ 0.7760 ≥ 0.70 ⇒ 结构可达"这句，正确读法是
  **上限区间 0.719–0.776 ≥ 0.70**——**仍然可达，但余量比单点值暗示的薄得多**
  （单点看余量 0.076，重复跑看只剩 0.019，还压在噪声带 0.057 之内）。
* 第三方给的质量路线**第 3 步**的基线"≥3 相关查询数 **38 → ≥48**"里那个 `38`
  自带 **±6 条查询**的抖动 ⇒ 判"有没有涨"要按重复跑的区间判，不能拿单点对单点。
* 第三方第 1 步要求"**重复 3 次、极差 ≤0.02**"：**E1@3 这条指标现在过得去（0.0104），
  上限这条现在过不去（0.0573）**——上限类结论要按区间说话。
