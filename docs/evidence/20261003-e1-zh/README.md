# E1 第一次量到非零：中文检索线索（2026-10-03）

## 这是什么

`tools/kb_fetch/case_search_zh.py` 为 L3 的每条案例生成一句**中文检索线索**
（只是检索键；返回给模型的仍是作者的英文 `excerpt`）。在这之前，产品的查询是中文散文、
而案例层 `CaseIndex._text` 只吃作者写的字，**BM25 对中文查询恒 0 命中**——E1 连分母都没有。

## 数字（同一套跨族面板：deepseek-chat ＋ glm-4.7，逐条 1–5 分，≥4 记为相关）

| 口径 | 分母 | ≥4 | 值 |
|---|---|---|---|
| **中文查询（产品的真实查询）** | 18（6 镜 × top-3） | **3** | **0.1667** |
| 同语言对照（英文查询打英文语料） | 18 | 0 | 0.0 |

* `reviews.jsonl` 与 `reviews_run1.jsonl` 是**两次独立运行**，都是 3/18，而且
  **命中的是同样三条**（`case_what-is-a-steadicam-shot_005`、
  `case_what-is-an-eyeline-match_008`、`case_what-is-an-eyeline-match_023`）——
  不是抽样噪声。
* `en_control.jsonl` 是同一时刻的英文对照（同一批查询的英文改写打英文语料）。
* 在此之前：中文查询 **0 命中**（分母 0）；同语言对照 1/18 → 0/18（见
  `ACCEPTANCE_STATUS.md` §三十.4）。

## 结论怎么读

* **不再是 0**：中文查询第一次真的召回了案例，E1 从"无法测量"变成"可测量且不达标"。
* **仍然离 70% 很远**（0.167 vs 0.70）。召回的 18 条里一半是 1–2 分（1900 年代书本散句、
  与查询无关的段落）——检索面接上了，**语料的适配度**是下一层问题。
* 门限一个字没动；E1 仍记 `not_measured`（它是人工/面板裁决项，链上不判过）。
