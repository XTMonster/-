# P14-89b：E1 的判分样本 **18 → 192**——诚实的读数比原来**更低**

## 为什么以前跑不了

E1 的分母是"这一跑**实际返回**的案例"，评审必须**跨族**（deepseek ＋ glm）。
旧面板默认第二个族是 `glm-4.7`，而本账号**只有 `glm-5.3` 还有额度**——
`glm-4.7` 返回 `HTTP 429 余额不足或无可用资源包`，于是整条通道一直停在
`reviews.jsonl` 那 18 条（6 个查询 × top-3）的老样本上（§七十八 记账）。

用户裁决"**GLM 只用 glm-5.3**"之后，这一轮把面板的默认模型换成 `glm-5.3`
（`tools/knowledge/e1_panel.py::DEFAULT_PANEL`，以及 `kb_fetch/llm.py` 等处的
默认，见 §八十七），一次跑完：

```
python tools/knowledge/e1_panel.py \
    --project docs/evidence/20261004_chunked_long19/project/project.bdproj \
    --out docs/evidence/20261004-e1-long19/reviews.jsonl --top-k 3 --limit 0
  → {"queries": 64, "scored": 192, "relevant": 17, "value": 0.0885, "line": 0.7}
```

## 新读数（192 条，同一判据、同一条线 0.70）

| | 旧样本 | **新样本** |
|---|---|---|
| 判分条数 | 18（6 个查询） | **192（64 个查询）** |
| 相关（≥4） | 3 | **17** |
| E1 | 0.1667 | **0.0885** |
| 距 §4.1b 下界 1200 | 差 1182 | **差 1008** |

**样本变大之后数字变差**——这正是"小样本乐观"的教科书形状。17 条相关的分布：

```
1.0×36  1.5×30  2.0×52  2.5×27  3.0×18  3.5×12  4.0×8  4.5×6  5.0×3
≥4：17 条   ≥3：47 条
64 个查询里只有 17 个"至少有一条 ≥4"
```

⇒ **语料适配度是下一层问题**（§八十七 记）：这套片子 64 个查询里，**47 个**
在这版案例语料里连一条"沾边以上"（≥4）的都找不到。判据、门限、oracle 一个字没动。

链上 `--e1-reviews` 已换到这一份（字面路径，守卫照旧验"文件存在且非空"），
所以链账里的 E1 从此是 192 条样本上的读数。
