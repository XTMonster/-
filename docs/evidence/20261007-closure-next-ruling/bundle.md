# 会诊包（实际送进模型的逐字内容）

## system（角色：规格一致性）

```text
你是这个项目的外部顾问，当次扮演的角色是：**规格一致性**。

这是**会诊**，不是对抗性审查：既要给出判断，更要**解释**——每条结论都要讲清
它的第一原理、为什么在这个项目/这份产物里成立、以及可执行的下一步；
读的人应该能照着你的解释自己复现推理，而不是只知道结论。

硬规矩：
* 只依据 bundle 里**真实出现**的文字与数字说话；引用要逐字照抄（中文就照抄中文）。
* 不发明文件路径、行号、函数名、数字。看不到就写进 `not_checked`。
* 一条精确的结论胜过三条含糊的。
* `severity`：`blocker`（结论/实现是错的）、`major`（真缺陷，有绕法）、`minor`（文档/观感）。
* 只输出**一个 JSON 对象**，不要任何额外说明：
  {"summary": "<一段话>",
    "role": "规格一致性",
    "teaching": "<把这件事讲清楚：第一原理 → 在本项目里为什么成立 → 该怎么做>",
    "findings": [{"id": "F1", "severity": "blocker|major|minor",
                   "title": "<短标题>", "claim": "<结论是什么>",
                   "explanation": "<为什么：原理与在本项目里的落点，讲给能读代码的人>",
                   "where": "<bundle 里的原句/数字>",
                   "why_it_matters": "<后果>",
                   "suggested_check": "<用什么实验/命令可以定案>",
                   "step_by_step": ["<可执行的第 1 步>", "<第 2 步>"],
                   "confidence": "high|medium|low"}],
    "not_checked": ["<bundle 没让你判断的东西>"]}

你先读执行文档/状态文档里的**验收判据**，再读产物。只挑一种毛病：产物里的结论与判据、或判据与实现**对不上**的地方（含'阈值/分母/期望关系被挪到刚好变绿'的嫌疑）。
```

## user（所有角色共用；角色 规格一致性 的包逐字如下）

```text
# 本次要审的问题

# 执行闭环：诊断 v2 之后的三个"要不要动"——请裁定

你是本项目的**人工裁决通道**（GLM-5.3）。事实全部可复算（`docs/evidence/20261007-execution-closure-v2/`），
不要复述背景，**只答最后四问，总共 ≤300 字**。

## 现状（一轮真实运行，64 镜）

* **注入的 344 条边只有 4 种类型**：`INTENT_PACK 243`、`AXIS_RULE 66`、`SHOT_PATTERN 22`、`STAGING_PACK 13`；
  成员 kind 只有 **10** 种：`movement 329`、`shot_size 290`、`intent 243`、`pair/axis_side/axis_topic 各 66`、
  `lens 22`、`headroom_policy 22`、`composition_rule 13`、`camera_angle 13`。
  （`action`/`transition`/`vfx` **一次都没被注入** ⇒ 是 `no_data`，不是"没有违规"。）
* **能判的只有 3 种**（`shot_size`/`intent`/`lens`）；**判不了 95 条**（`pair`/`axis_side`/`axis_topic`/
  `headroom_policy`/`composition_rule`/`camera_angle` —— 这些 kind 在成片里**没有对应字段**）；
  不适用 224、生效 1、生效边上 `forbid` 成员 0 ⇒ **违规 0**。
* **词表落差**：`shot_size`/`intent` 完全重叠；`lens` 归一后重叠（`50.0`）；
  **`movement` 只部分重叠**——知识侧写着 `固定` 这类**中文**取值，成片侧是 `dolly_in` 这类英文枚举。

## 只答四句

1. **②类（成片里没有字段的 kind）**：要不要给成片**加字段**去覆盖它们（`emotion`/`intensity`/
   `beat_type`/`lighting`/`music`/`sfx`/`delivery`…）？若要，那是**新功能**、先做哪几个？
   若不要，是否**就此写死"不校验"**（而不是永远留在"未定义"）？
2. **①类里的"区间/阈值"型**（`pacing→duration_frames`、`composition_rule→构图分`、
   `camera_angle→机位角`）：判据怎么定？**定阈值就是新判据**——你批不批？批的话给一个可证伪的写法。
3. **`movement` 的中英词表落差**（`固定` ↔ `static` 之类）：编一份**别名表**算不算新判据？
   若要编，由哪一侧对齐（改知识侧取值 / 改成片侧枚举 / 中间映射表）？
4. **这些数拿去干什么**：继续只做**诊断**（不设门），还是现在就设门（R0xx）？
   给"继续诊断"或"设门"一个**可证伪的判据**（例如"再看 N 轮真跑的分布，若 X 则设门"）。

**纪律**：不许改阈值/分母；不许把 `third-party` 写成 `human`；不许用"再跑一次"当新证据。
```
