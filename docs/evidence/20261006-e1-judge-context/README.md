# E1 的尺子随 `--top-k` 变：评委看到的候选越多，分给得越高

日期 2026-10-06。本目录是**审计发现**：它说明 `docs/evidence/20261006-e1-ceiling/` 那条
"完美重排上限 0.7760 ≥ 0.70 ⇒ 结构可达"证书里，**上限与 E1 不在同一把尺子上**。

## 事实

两份打分文件来自**同一条检索**：

| | 文件 | `--top-k` | 面板 | 判分提示词 sha | `cases_fingerprint` / `digest` |
|---|---|---|---|---|---|
| P | `docs/evidence/20261005-e1-filter/reviews.hybrid.unfiltered.rep1.jsonl` | **3** | deepseek-chat + glm-5.3 | `9a27df1c…` | `4b1b44bb…` / `d916cd78…` |
| Q | `docs/evidence/20261006-e1-ceiling/reviews.hybrid.top20.rep1.jsonl` | **20** | 同上 | 同上 | 同上 |

把 P 与 Q 的**前 3 行**逐条对齐后（`python -c` 逐行比对，见下）：

* **192/192 条 `(query, case_id)` 三元组相同**（BM25 确定性 ⇒ 前 3 条就是同一批）；
* **192/192 条 `excerpt` 与 `zh` 逐字节相同**⇒ 案例内容没变；
* 但**评分不同**：83/192 行同分、109/192 行不同，差值分布
  `{-1.0:6, -0.5:26, +0.5:55, +1.0:16, +1.5:6}`——**净向 +33.5**（不是对称噪声，是整体上移）。

⇒ 同一批候选、同一位评委、同一条提示词，只因为**同一次调用里还塞了另外 17 条候选**：

| 评委 | `--top-k 3` 时的均值 / 相关率 | `--top-k 20` 时的均值 / 相关率 |
|---|---|---|
| `deepseek-chat` | 2.547 ／ 33/192 | **2.807** ／ **58/192** |
| `glm-5.3` | 3.050 ／ 61/179 | **3.165** ／ **75/176** |

**两位评委会同向漂移**（都往上）⇒ 不是某位评委的偏好，是**候选清单长度**这个共同因素。

## 这意味着什么（对 R3 的两条影响）

1. **不同 `--top-k` 的 E1 不能互相引用。** 台账 R3 行把 `基准 0.1927`（top-3 尺子）与
   `上限 0.7760`（top-20 尺子）并排放在一起——**那是两把尺子**。
2. **"上限"是乐观口径。** 上限由 top-20 分数导出（评委看得见 20 条，给分高）；
   而产品实际量的是 **top-3** 的 E1（评委只看 3 条，给分低）。一个完美重排器把 20 条里
   最该看的 3 条挑出来后，评委**仍然只在 3 条的语境里**打分 ⇒ 它能拿到的 E1
   **低于** 0.7760。所以"0.776 ≥ 0.70 ⇒ 结构可达"这句**不能用这份证书支撑**。

## 已跑 / 在跑的判定

* **已排除了三个替代解释**：检索序（64/64 case_id 同）、案例内容（excerpt/zh 逐字节同）、
  判分提示词与面板（sha 同）。
* **仍在跑的控制实验**：在**同一批语料**上重跑一次 `--top-k 3`（`work/ab_e1_candidates/hybrid.top3.v4.ctl.jsonl`）。
  若它回到 ~0.19，则"清单长度"是唯一站得住的解释（检索序相同、只差 k）；
  若它也给出 ~0.28，则要另找原因（例如评委后端在那几小时里换过版本）。
  **跑完补进本表**。
* **未验证**：这个漂移是**单调**于 k 的（已测 3 与 20 两点）；k=8/50 两点在跑。

## 口径（不改判据）

判据一个字没动：相关仍是"两位评委 1–5 分取均值 ≥ 4.0"，红线仍是 E1 ≥ 0.70，
分母仍是面板条目数。本目录只声明**一句可比性条件**：**报 E1 必须连同它是在多少条候选
的语境里判的**；跨 k 的数字不许直接相减、相除、当上界。
