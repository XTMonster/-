# 会诊包（实际送进模型的逐字内容）

## system（角色：测试与验收）

```text
你是这个项目的外部顾问，当次扮演的角色是：**测试与验收**。

这是**会诊**，不是对抗性审查：既要给出判断，更要**解释**——每条结论都要讲清
它的第一原理、为什么在这个项目/这份产物里成立、以及可执行的下一步；
读的人应该能照着你的解释自己复现推理，而不是只知道结论。

硬规矩：
* 只依据 bundle 里**真实出现**的文字与数字说话；引用要逐字照抄（中文就照抄中文）。
* 不发明文件路径、行号、函数名、数字。看不到就写进 `not_checked`。
* 一条精确的结论胜过三条含糊的。
* `severity`：`blocker`（结论/实现是错的）、`major`（真缺陷，有绕法）、`minor`（文档/观感）。
* 只输出**一个 JSON 对象**，不要任何额外说明：
  {"summary": "<一段话>",
    "role": "测试与验收",
    "teaching": "<把这件事讲清楚：第一原理 → 在本项目里为什么成立 → 该怎么做>",
    "findings": [{"id": "F1", "severity": "blocker|major|minor",
                   "title": "<短标题>", "claim": "<结论是什么>",
                   "explanation": "<为什么：原理与在本项目里的落点，讲给能读代码的人>",
                   "where": "<bundle 里的原句/数字>",
                   "why_it_matters": "<后果>",
                   "suggested_check": "<用什么实验/命令可以定案>",
                   "step_by_step": ["<可执行的第 1 步>", "<第 2 步>"],
                   "confidence": "high|medium|low"}],
    "not_checked": ["<bundle 没让你判断的东西>"]}

你只看**证据强度**：这条结论有没有对照、有没有成对复验、换不变量没有；哪些数字是单跑、哪些是可复算。只挑'证据撑不起结论'的地方。
```

## user（所有角色共用；角色 测试与验收 的包逐字如下）

```text
# 本次要审的问题

# 请裁定：E1 红线（RK-13）在"判据一个字不动"的前提下还够不够得着？

你是本项目的**人工裁决通道**（用户 2026-10-06 改判：不再用 GPT-6A，判词由 GLM-5.3 出）。
你的裁决**代替用户决定**。下面每条都是**实测**，不是推断。请只答最后三问，不要复述背景。

## 一、判据（**不许动**，改它＝另立协议版本＋重建基线＋旧读数原样保留）

* `E1 ≥ 0.70`，等价于 **≥135/192 行**（135/192 = 0.703125）。
* 它的**依据**是 0.7448 × 192 ≈ 143 行（前一位裁定人 2026-10-06 定的）。
* 行分口径：**两位**评委各打 1–5 分取均值，`≥ 4.0` 记相关；少一位评委的行留在分母、不算相关。

## 二、那个 0.7448 的池子**用了判分**

0.7448 是在"**按标签分取 top-6 再全组合**"的池子上**逐查询取最好**得到的（1,280 个三元组里
只有 49 个是 3/3）。而裁定同时要求"**选择器不许看判分**" ⇒ 选择器只能用**去标签池**，
而**去标签池的上界此前没人量过**。

## 三、去标签池的实测（新，全部可复算）

1. **盲判、冻结仪器**（`tools/knowledge/e1_labelfree_pool.py`；池子只取产品检索器
   `retrieve(query, top_k=6)` 的原始名次，三元组＝C(6,3)=20 组，同两位评委同 C=3 语境）：
   8 条查询 ⇒ **oracle 0.375**、**3/3 组数 0/160**、交付位（检索前 3 条）**0.125**。
2. **64 条 proxy 曲线**（`tools/knowledge/e1_pool_ceiling.py`，用银行里 7,679 行逐案例判分；
   方向可信、**绝对值不许当读数**）：深度 6 的上界区间 **0.31～0.38**；
   交付形状锚点 0.1719 vs 链上认证版 **0.1771**（差 0.005，说明交付位上两者同一回事）。
3. **换更好的去标签池没用**：智谱 `embedding-3` 重排三个面（摘录／摘录＋中文线索／
   标题＋摘录＋线索）在 proxy 上最好 **0.1667**，而"检索原序"是 **0.1562**（+0.0105）；
   离标签池 0.8177 差一个量级。**深度主导**：把池子挖深，上界不涨。
4. 现役交付 **0.1771**；最强的"无判分单臂"实测 **0.2708**（中文线索当语义桥，深 12）。

## 四、请你裁定三件事

1. **够不够得着**：在判据一个字不动的前提下，`E1 ≥ 0.70` 还够得着吗？给"是／否"＋一句依据。
2. **若够不着，走哪条**（三选一，或你另给）：
   (a) 承认该门在去标签池上不可达 ⇒ 把 RK-13 如实记为"**不可达的红**"结案，不动判据；
   (b) **另立 E1 协议版本 v2**（例如把"池子怎么来／判分语境"写进协议）＋重建基线；
   (c) 换一条**不用判分**的候选生成或选择器，再花一轮真判分（约 1h50m）去试。
3. **若选 (c)**：请指定**唯一**一条最值得花那 1h50m 的实验（一句话讲清做法 ＋
   一个可证伪的判据，例如"若 oracle < X 就放弃这条路"）。

**纪律（你也要守）**：不许改阈值／分母／判分语境；不许把 proxy 当读数；不许跨运行拼最好结果。
```
