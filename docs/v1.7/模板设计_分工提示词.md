## 1. 先承认复杂性：耦合面全表

模板正文看起来是"写五句话"，实际上每个占位符都是一个耦合点。**先把耦合面全部摊开，再设计正文**——哪个来源变了会咬到模板，一目了然：

| # | 耦合面 | 数据源 / 产出卡 | 失效模式 | 设计对策 |
|---|---|---|---|---|
| C1 | 目标模型规格 | `specs/target_models.yaml`（A5）/ `delivery.target_model` | 未知模型值；模板文件缺失 | I4 已钉回落 seedance_2.5；模板文件缺失抛 `TargetModelError` 同款结构化错（不静默） |
| C2 | 计划镜数 | `plan.shots`（A6） | 与视频段数不一致（见 C3） | 标题行同时带 `$shot_count` 与 `$rendered_count`，不等即自明 |
| C3 | skip 声明 | `shot.responsibility.skip_white_model`（J3） | skip 镜无白模视频，模型按镜数对不上 | 不等时 package.py 在标题行下插一行清单式说明（不算正文句数）＋指针到 responsibility.md |
| C4 | 切片建议 | `target_advisor.suggest_slices`（I4） | 无超限时占位空 | `$slice_sentence` 槽：空 → 整句删除（渲染后处理，§4） |
| C5 | 参考图资产存在性 | `delivery.reference_cards`（config.py:320 实读，默认开）/ 定妆卡产物 | 关了定妆卡，模板却指着不存在的图 | `$authority_sentence` 槽按资产存在性选变体（§3），句子在 package.py 组装 |
| C6 | 导出形态 | `delivery.per_shot_clips`（:323）/ `full_concat`（:325） | 分段/整片两种喂法说明不同 | 分段说明归 README（清单文不占句数），正文句不随它变 |
| C7 | 运镜文字 | I2 `camera_narration` → shots.json/shot_cards.md | 模板若复述运镜，就会与实测产生第二真源 | **刻意解耦**（§5.1）：模板零运镜内容，运镜只活在镜头卡 |

## 2. 信息架构：2 句静态 ＋ 2 槽 ＋ 标题/清单行

五句预算（A-E1-3）这样分配：

- **标题行**（清单行，不计句数）：身份声明——这是什么包、几镜几段；
- **句 ①（取用清单，静态）**：P1 核心句的正向转写——取什么；
- **句 ②（占位符声明，静态）**：P1+P2——几何体是占位符；**颜色条款反向利用**：本仓角色本就有色板色（`panel_cast.py` 的 color 字段），与其防颜色渗透不如声明"同色即同人"，把颜色从污染源变成跨镜身份追踪资产；
- **槽 A（权威句，1 句）**：P14 职责分区的收口——外观/表情/动作细节看参考图与镜头卡，风格色调看风格图；两个分句各有"资产不存在"变体（C5）；
- **槽 B（规格句，0–1 句）**：C4 切片建议；不超限时整句消失。

**为什么槽而不是条件模板**：`string.Template` 没有条件语法，而模板文件必须**完整可读**（它是数据文件，评审时人读的就是它）。折中：静态句在文件里，条件句整句作为占位符由 package.py 注入——模板读起来仍是完整骨架。

## 3. 模板正文（三模型同构，差异只在规格句措辞）

`specs/prompt_templates/seedance_2.5.txt`：

```text
# $target_label 白模参考包 · 共 $shot_count 镜 / $rendered_count 段白模视频
参考视频里只取四样：运镜的起点方位、运动路径与终点方位，镜头切换点，节奏与时长，人物与道具的摆放位置。
画面中的几何体全部是占位符；占位符颜色仅用于区分角色身份（同色即同人），不代表最终外观、材质与色调。
$authority_sentence
$slice_sentence
```

槽的取值（package.py 组装，钉死措辞）：

| 槽 | 条件 | 文本 |
|---|---|---|
| `$authority_sentence` | 定妆卡存在 ＋ 有风格图 | `角色外观、表情与动作细节，以随包角色定妆卡与逐镜镜头卡（shot_cards.md）为准；场景风格与色调以风格参考图为准。` |
| 同上 | 定妆卡存在 ＋ 无风格图 | `角色外观、表情与动作细节，以随包角色定妆卡与逐镜镜头卡（shot_cards.md）为准；场景风格与色调以镜头卡文字描述为准。` |
| 同上 | 无定妆卡 | `角色外观、表情、动作细节与场景风格，一律以逐镜镜头卡（shot_cards.md）的文字描述为准。` |
| `$slice_sentence` | 未超限 | `""`（整句删除） |
| 同上 | seedance_2.5 超限 | `时间线超出单段上限，已建议切为 $slice_count 段（切点全在镜头切换处，见 README）；逐段喂入并保持段序。` |
| 同上 | kling | `……按 5/10 秒档位组织为 $slice_count 段……`（其余同构） |
| 同上 | hailuo_h3 | `……按 4–15 秒段组织为 $slice_count 段，注意参考文件预算（图 9 / 视频 3 / 音频 3）……` |

句数核算：静态 2 句 ＋ 权威 1 句 ＋ 规格 ≤1 句 = **恒 ≤4 句**，留 1 句余量给未来，A-E1-3 稳过。

`kling.txt` / `hailuo_h3.txt` 与上同构——**三份文件当前只有槽的措辞不同**，分开成文件是为了未来分化（参考预算句、官方白模规范对接）不动代码（NFR-6）。

## 4. 渲染纪律（package.py，I3 落地）

1. 用 `Template.substitute`（**不是** safe_substitute）：缺键抛 KeyError——配置/组装错误要当场炸，不静默（对齐 `TargetModelError` 纪律）；
2. 渲染后处理：删除因空槽产生的空行，连续空行压一行；
3. skip 说明行（C3）：`$rendered_count < $shot_count` 时由 package.py 在标题行下插
   `（其中 K 镜声明直出提示词＋参考图，无白模视频，见 responsibility.md）`——清单行，不计句数；
4. **句数测试口径（钉死）**：渲染结果去掉 `#` 标题行与 `（…）` 清单行后，中文句号 `。` 计数 ≤ 5——进 `tests/test_reference_pack.py::test_template_fields` 的断言；
5. 变量全表（共 6 个，I3 卡"≤6 占位"上限内）：`$target_label` `$shot_count` `$rendered_count` `$authority_sentence` `$slice_sentence` `$slice_count`。

## 5. 两个刻意解耦的决定

### 5.1 运镜零进模板（C7/C8 的免疫设计）

模板正文**不含任何具体运镜/站位描述**——运镜只经 I2 文字化器进 `shot_cards.md` 与 `shots.json.camera_narration` 单真源。收益：

- R025（J4，提示词 vs 实测矛盾）对模板**结构上免疫**——静态元指令无方位可错；
- 模板不随镜头内容再生成，golden 对拍稳定（只有槽变量变化）；
- 镜头卡改文案不需要碰模板文件。

### 5.2 分工细节不进模板

`responsibility` 的三清单（white_model/prompt/ref_image 逐镜明细）全部在 `responsibility.md`，模板只留一行指针（C3 的清单行）。理由：模板是喂模型的**元指令**，逐镜分工是人读的**交接文档**——两个受众、两种粒度，混在一起两头都读不好。

### 5.3 角色为什么不在模板正文里（2026-10-10 补）

模板正文通篇没有角色名、角色设定——**这是刻意的，不是遗漏**。按 P14 职责分离，角色信息各有真源，模板若复述即成第二真源：

| 角色信息 | 真源 | 模板只做什么 |
|---|---|---|
| 外观/表情/服装 | 角色定妆卡（`delivery.reference_cards`，config.py:320） | `$authority_sentence` 指过去 |
| 动作细节/台词/表演 | 逐镜镜头卡 shot_cards.md ＋ 既有 prompts.md | 同上 |
| 跨镜身份追踪 | 占位符颜色（句②"同色即同人"） | 已在正文 |
| 逐镜分工边界 | responsibility.md（J3） | C3 清单行指针 |
| 谁在画面哪侧/朝向 | continuity.json | 不提及（机器对拍用） |

**但存在一个真缺口（本版补钉）**：句②"同色即同人"成立的前提是读者能把**角色名 ↔ 占位色 ↔ 定妆卡文件**对上——这个对照此前散在 elements.json（机器读）与镜头卡（逐镜读）里，包的读者面没有一处显式名册。钉死：**README.md 必含"角色名册"区**（清单文，不占正文 5 句预算），列为一张表，列序固定：**角色名 / 占位色 / 身高 / 定妆卡文件 / 出场镜号**；**数据源 = elements.json**（SC-06 单一元素登记表，不新造第二份）。若定妆卡关闭，名册的"定妆卡文件"列写"（未生成）"。

**"身高"列的口径（2026-10-10 二轮细化钉死，用户裁决"加进去"）**：值 = 冻结几何 `character.total_height`（ADR-0007 冻结 **1.70 m**，派生真源 `cinema/anchor.py`），格式两位小数（`1.70`）。当前 CastMember（contracts/cast.py:287-307）**无个体身高字段**，所以名册中所有角色同值——这是刻意的：身高列的存在意义不是区分角色，而是给 **R020（白模比例核验）** 一个人读的核验基准（"画面中所有白模角色都应与名册身高一致"）。注释里必须写清来源：未来引入个体身高（角色 spec 化）时，此列改读角色 spec，名册生成代码只改一处取值。

同时钉死反向纪律：模板与名册**都不新增"角色一句话设定"字段**——人物设定只从剧本/SceneBrief 来（经镜头卡承载），不在导出层新造描述真源。

## 6. 语言决策

默认**中文**（用户工作流中文；Seedance/Kling/Hailuo 均为国产模型，中文提示词是一等公民）。文件名即语言：`seedance_2.5.txt` = 中文；未来若要英文版，新增 `seedance_2.5.en.txt` 文件即可，代码零改动。记移交事项，不阻塞。
