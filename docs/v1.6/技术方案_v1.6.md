## 0. 全局技术判断

1. **三个新方向都不需要推翻现有架构，全部落在已有的分层骨架上**：
   节奏（FR-B）长在 `contracts/beats.py` + `beat_compiler.py` + `cinema/camera_motion.py` 这条"语义 → 编译 → 关键帧"链上；
   视锥校验（FR-C）长在 `cinema/composition.py` + `layer3_engine/shot_auditor.py` + `repair.py` 这条"评分 → 审核 → 修复"链上；
   元素统一（FR-A）长在 `scene_executor`（环境构建）+ `layer8_delivery`（交付包）这条链上。
   **结论：全部是"加层/加字段/加产物"，不是改造。**
2. **一切 LLM 可见的新自由度都做成闭集**（pace、curve、方位、节奏档案）。依据：E-run ③ 证明开放数值/自由命名是 invalid 的重灾区；`contracts/beats.py` 的模块 docstring 已把这条写成方法论（"连续数值是幻觉温床"）。
3. **测量与裁决分离**：几何层只报"现象 + 数值"，LLM 只做语义裁决（R-构图 TL;DR、§4.1；自纠错研究的 verify-judge-correct 结构）。这正好治 E-video P1-1（"判红后模型反复试仍不过"——因为它拿到的是分数不是证据）。

### 1.2 机制设计

* **元素登记表（`elements.json`）**：构建完成后由 `SceneContext` 现成数据导出——角色（id/名/颜色/圆柱身参数）、道具（id/形状/所属镜）、环境件（id/方位闭集值/尺寸档）。**确定性**是硬要求：同一计划导出逐字节相同（复用 `delivery/manifest.py` 的排序与序列化纪律）。
* **逐镜元素映射**：`shots.json` 每镜已有 `characters`；补 `elements_in_frame`（道具+环境件），来源是构建时的 collection 归属，不做事后图像推断。
* **遮罩通道**：`layer8_delivery/mask_pass.py`（新）：与深度 pass 同引擎、同事务纪律——渲染前快照每个角色/道具物体的材质槽，挂上按 `elements.json` 色表生成的纯色自发光材质（每元素一份，命名 `BD_Mask_<element_id>`），环境件统一中灰、`world_override` 纯黑、标签与辅助件 `hide_render=True`，逐镜渲染 PNG 序列后恢复原现场。**颜色即身份**：下游视频模型换风格时，mask 色块就是"谁在哪"的锁定信号。
* **提示词稳定 token**：`prompts.md` 生成时头部插"元素表"（从登记表渲染），逐镜描述里的角色/道具名必须来自登记表键；`delivery/prompts.py` 加一个对拍校验（复用 P15 的逐字段对拍机制）：描述句里出现表外名字 ⇒ error。

### 1.3 与缺陷修复的联动

FR-A1（环境骨架 + 方位闭集 + 失败回报）同时就是 D-10；D-11（占位角色硬校验）是元素统一的前置——登记表里有 `char_a` 就等于登记失败。

## 2. FR-B 节奏规划

### 2.1 三层模型与落点

```
剧本节奏（script）  → SceneBrief.rhythm_arc[]      → 计划提示注入 + 镜长建议带
镜头节奏（shot）    → pacing_profile + 时长诊断     → plan 校验/readings（info 级）
镜内节奏（action）  → ShotBeat.pace × curve         → beat_compiler → 帧长 + fcurve 插值
运镜节奏（camera）  → camera.movements[].curve      → camera_motion 写关键帧时设插值
```

### 2.2 选型结论

| 决策点 | 选择 | 依据 |
|---|---|---|
| 节奏表达 | **闭集词 + 确定性编译**，LLM 永不直接写插值参数 | 同 §0.2；`pace` 三档已在跑（`PACE_TO_SPEED`），证明"语义词 → 引擎参数"这条路在本项目成立 |
| 速度曲线闭集 | `linear / smooth / ease_in / ease_out / sharp` | 覆盖"蓄-发-收"（E-video P1-4 点名）与突发动作；`motion/model.py` 内部已有 `_ease` 数学，缺的只是 LLM 可见词表与 fcurve 落点 |
| fcurve 落点 | Blender 关键帧 `interpolation`：`smooth→BEZIER`、`linear→LINEAR`、`sharp→CONSTANT 起步 + LINEAR 主体`（或 BEZIER + 急手柄，实现细节钉在 TDD）；运镜现状已一律 BEZIER（`cinema_engine/camera_motion.py:88-89`），即现状 = `smooth` 档 | 不重造轮子；24 种运镜的纯求解层（位置/看向/焦距）完全不动 |
| 镜长诊断 | ASL / 镜长方差 / 单调性，**全部 info 级**（跳切风险的逐镜头对告警归 FR-C6 的 warning 级，节奏读数里只计数不告警） | ASL 证据带（动作 2–4 s、剧情 6–10 s、好莱坞 8–12 s）是**统计参考**不是规则；PRD §3.2 已立"节奏不设硬门" |
| 剧本节奏弧 | Stage S schema 加 `rhythm_arc[]`；失败回退 `deterministic_rhythm()`（台词密度 + 走位距离分档），记 `E_BRIEF_002` | 完全复刻 v1.5 Stage S 的"理解失败 → 确定性回退 + 事件码"范式（`understand.py` 的 `E_BRIEF_001` 路径） |

### 2.3 一个明确的边界

**节奏诊断不进通过/不通过**。理由：节奏是创作选择（调研资料一致：紧 headroom/大留白都是手法），本项目已有"规则是用来被有意识地打破的"先例（`declared_breaks`）。诊断的唯一使命是让 LLM 在**知情**的状态下做选择——与 FR-C 的"只报现象"是同一哲学。

## 3. FR-C 时间轴视锥构图校验回路

### 3.1 分层设计（红线：纯层零 bpy）

```
cinema/frustum_metrics.py   【纯】输入 2D 包围盒序列 → 六项度量 + 四类曲线事件 + 告警 DTO
layer3_engine/frustum_sampler.py 【bpy】frame_set 逐帧 → depsgraph 求值 → world_to_camera_view 投影
                                  → BVH 射线可见比例 → 喂给纯层
layer3_engine/shot_auditor.py    【改】审核失败时把结构化告警（而非分数）挂到 AuditResult
layer5_orchestrator/repair.py    【改】修复提示注入告警证据 + 参数化 reframe 菜单
```

* **投影一律用 `bpy_extras.object_utils.world_to_camera_view`**（已封装 shift/焦距/传感器/像素比/正交，R-构图 §5 明确警告不要自写矩阵）；相机后方的点 z<0，单列硬错误（R-构图 §3.1 的仿真结论）。
* **采样必须读 depsgraph 评估后的 `matrix_world`**（`evaluated_depsgraph_get` + `evaluated_get`），否则约束/驱动器驱动的动画帧包围盒"不报错地错"（R-构图 §3.1，CGWire 技术博客）。
* **采样策略**：隔帧（步长可配，默认 4 帧）+ 事件帧加密（相机/主体关键帧、速度极值点）；100 帧量级 < 5 s（NFR-3）。
* **遮挡**：沿用现有 `scene.ray_cast` 路线（composition 的 occlusion 权重项已由调用方传入），升级为**可见比例**（包围盒采样点的可见占比），告警两级：主体被挡 >20% 且未声明前景遮挡 ⇒ warning；包围盒在画内但可见比例 0 ⇒ error（R-构图 §3.3）。

### 3.2 告警 DTO 与裁决回路（核心机制）

```json
{
  "shot_id": "shot_004", "frame_range": [1, 48],
  "type": "framing_too_tight", "subject": "米迦尔",
  "evidence": {"head_height_ratio": 0.93, "expected_range": [0.55, 0.75], "lens_mm": 85},
  "severity": "warning", "confidence": "high",
  "declared_intent": "CU：面部特写",
  "suggestion_hint": "拉远相机或降焦段：head_height_ratio 每 +0.1 ≈ 距离 ×0.88"
}
```

三条设计纪律（都来自 R-构图 §4 与 E-video 的教训）：

1. **告警三要素缺一不可**：数值证据（让 LLM 量化权衡）、声明意图并置（让它能做语义裁决）、修复提示（降低重新搜索解空间的成本）——hint 只是 hint，改不改由 LLM。
2. **防告警疲劳**：error 必须处理 / warning 由 LLM 裁决 / info 默认不打扰；同镜同类按时间范围合并；包围盒保守虚胖的度量标 `confidence: low`。
3. **阈值不是法律**：三档风格预设（strict/standard/loose）由计划在剧本级选定；LLM 显式拒绝告警时记 `guard_verdict{accepted: false, reason}`——裁决记录持久化，未来可做阈值自校准（R-构图 §5 第四期，本版只做记录不做学习）。

### 3.3 镜头间校验（治 E-video P1-2 的根）

现状：轴线判定用"当前两人连线"与计划的 `axis_note` 文字自述比对——**两者没有共享可观测量**（E-video P1-2；v15 台账 §70 同形结论）。
修法：**银幕左右序状态机**——可观测量只有"角色包围盒中心的画面 X 半区 + 头部朝向向量投影到画面 X 轴的符号"（R-构图 §3.5：这组二元量能抓住绝大多数对话戏连续性错误）。逐镜维护"谁在左谁在右"的屏幕状态，正反打镜头比对前后镜的左右序是否保持；中性镜（正/背对相机，朝向符号 ≈0）合法桥接换侧。轴线规则引擎（`cinema/axis.py`）改为消费这个状态机，`axis_note` 降级为展示文本。

### 3.4 为什么不选"渲染图 + VLM 当主校验"

成本高（每轮一次渲染 + 一次多模态调用）、粒度粗（VLM 对"出画 24%"这类精确现象定位弱，易把缺陷说成"刻意风格"）、测量与裁决耦合互相污染（R-构图 §2.2/§4.3）。本项目保留 VLM 为**可选抽检**（`vlm_review` 已在），几何校验做常驻全量——混合策略的推荐形态（R-构图 §4.3 表）。

## 5. FR-E 圆柱身体的技术论证

* **依据**：v1.4 §7 D1b 已证明"等外接盒的圆角方体与圆柱**世界 AABB 逐位相同**"（`docs/evidence/d1b_body_shape/`，max_delta = 0.0）——当时选圆角方体是**观感**裁决（"块面感"），不是几何约束。用户现在改选圆柱，同样只动观感层。
* **改动面**：`character_factory.py::_add_rounded_box_body` → `_add_cylinder_body`（`bpy.ops.mesh.primitive_cylinder_add(radius=BODY_RADIUS, depth=BODY_HEIGHT, vertices=32)`），挂父级/材质/命名逻辑原样。
* **不变量**：`BODY_RADIUS=0.25`、`BODY_HEIGHT=0.748`、全部锚点（`cinema/anchor.py`）一个数字不动；AABB 量测脚本复跑，max_delta 必须仍是 0.0；全量 pytest 绿。
* **附带收益**：圆柱旋转对称 ⇒ `turn_body`/`body_tilt` 时侧面轮廓不再出现方体棱线的视觉跳变，对下游视频模型的"轮廓一致性"更友好（推断，无对照实验，标为假设）。

## 6. 风险与缓解（技术侧）

| 风险 | 概率 | 缓解 |
|---|---|---|
| 逐帧采样在大场景变慢（`frame_set` 触发全场景求值） | 中 | 隔帧采样 + 事件帧加密；depsgraph update tag 只重算变化物体（R-构图 §5）；NFR-3 的 5 s 预算进测试 |
| 告警阈值在不同剧本风格上误报 | 中 | 三档风格预设 + confidence 标注 + 裁决记录；误报治理是持续过程，不在 v1.6 承诺"零误报" |
| 重试阶梯的"瘦身包"裁掉关键上下文反而降质 | 低 | 瘦身只去 RAG 三栏，保留该镜声明/审计发现/工具结果；阶梯每步记审计，可回放归因 |
| 遮罩纯色与角色标签色不一致 | 低 | 色表单一真源 = `elements.json`，遮罩与标签都从它读 |
| 圆柱化后有人顺手"优化"锚点 | 低 | FR-E2 硬闸：AABB 量测 + 全量 pytest + `tests/test_agents_status_is_current.py` 类对拍 |
