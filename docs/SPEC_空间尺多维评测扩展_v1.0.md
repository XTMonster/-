# 空间尺多维评测扩展 SPEC v1.0

状态：设计规格（不包含实现承诺）  
范围：BlockDirector 白模预演中的外挂式空间尺评测台，先独立评测，验证有效后再整合进主流程。

## 读法与适用分支

本 SPEC 按任务分支阅读，不需要每次通读全篇：

- 实现/修改空间尺指标时：读 §4、§5、§6，指标细节经指针取《空间尺指标规范 v1.0》。
- 接入/维护外挂评测台时：读 §7、§8、§9 及 `tools/spatial_ruler_ab/`。
- 验收/判定效果声明时：读 §10、§11。

## 1. 背景与问题

现有空间尺包含六个单帧构图分量：`headroom`、`lead_room`、`rule_of_thirds`、`balance`、`occlusion`、`framing`。它们能判断“主体是否入画、留白是否合理、人物是否遮挡”，但不能充分回答：

- 打斗中谁攻击、谁受击、接触点是否可见；
- 追逐或运镜时运动方向是否连续；
- 对切镜头是否越轴、视线是否跳变；
- 多人场面中观众是否能快速识别叙事重点；
- 构图是否只在单帧成立，还是在整段动作中都稳定；
- 镜头是否完成了剧本要求的叙事意图。

本 SPEC 将空间尺定义为“多层测量 + 硬门 + 结构化处方”的外挂评测模块，而不是一个单一美学总分器。

### 1.1 真源映射

本 SPEC 是设计规格，不是实现快照；以下材料以代码/环境为真源，SPEC 只给指针，不重复定义：

| 材料 | 真源位置 | 说明 |
|---|---|---|
| 现有六项构图指标实现 | `block_director/cinema/composition.py` | 阈值与公式以代码为准 |
| 视锥度量/告警 | `block_director/cinema/frustum_metrics.py` | 单帧度量与事件检测 |
| 动态/打斗测量 | `block_director/cinema/dynamic_measure.py` | 轨迹/事件/遮挡/左右序 |
| 处方 demo 实现 | `block_director/cinema/prescription.py` | 与 §7 目标 schema 不一致，见 §12 |
| 方法卡 | `block_director/knowledge/cards_review_method.py` | MR 规则段 + 检查清单 |
| 外挂四臂评测台 | `tools/spatial_ruler_ab/` | 任务类型与提示渲染 |

## 2. 目标与非目标

### 2.1 目标

1. 保留现有六项指标及其阈值，不改变既有验收口径。
2. 新增几何、视觉可读性、动作因果、镜头连续性、摄影意图、鲁棒性六个维度。
3. 每项指标都有：定义、输入、测量值、目标区间、严重度、失败原因和可执行修复方向。
4. 支持单帧、镜头内关键帧序列（内容关键帧 + 动作关键帧）、镜头序列三种评测粒度。
5. 支持 baseline / ruler / method / ruler_method 四臂外挂 A/B 测试。
6. agent 只接收测量结果和方法论；正确处方答案只在复测阶段用于对拍，不进入尺子提示。
7. 允许将“几何合格但叙事不合格”明确分开报告。

### 2.2 非目标

- 不在本 SPEC 中定义最终审美偏好或替代导演决策。
- 每个维度独立报告分数，硬门与分层分数分离。
- 不用图像模型主观描述替代可复现的几何测量。
- 不允许通过降低阈值、删除失败样例或跳过场景来获得通过。

## 3. 核心概念

### 3.1 评测对象

- `FrameSample`：镜头中的一个采样帧，含相机、角色、道具、投影包围盒和可见性。
- `ContentFrame`（内容关键帧）：按镜头内容覆盖选取的采样帧，至少包含首帧、中帧、末帧；用于构图、视线、空间与稳定性评测。
- `ActionFrame`（动作关键帧）：按动作事件选取的采样帧，包括动作起点、接触点、反应结束等；用于动作与因果层评测。
- `ShotSample`：一个镜头的内容关键帧与动作关键帧的并集，至少包含首帧、中帧、末帧以及所有动作接触帧。
- `SequenceSample`：按剪辑顺序排列的相邻镜头集合，用于轴线、视线和运动连续性评测。
- `IntentContract`：剧本或分镜声明的镜头意图，例如“建立环境”“突出攻击者”“让观众看清受击反应”。
- `Measurement`：指标名、原始值、归一化分数、目标区间、证据帧和置信度。
- `Finding`：失败项及其严重度（fatal / error / warning / note）。
- `Prescription`：只描述可执行的工具方向、参数范围和预期影响，不写不可验证的自由文本。

### 3.2 三类结论

1. **硬门结论**：主体不可见、关键动作接触点不可见、越轴、目标完全出画等直接失败。
2. **分层分数**：用于比较优化前后，不直接替代硬门。
3. **导演备注**：风格或意图判断，可由 agent/人工复核，但不能伪装成几何事实。

## 4. 评测层级与指标

> 本节约 32 个新增指标的完整规格（粒度、输入、测量值、目标区间、严重度、失败原因、修复方向、证据等级）见《空间尺指标规范 v1.0》；现有 6 项指标以 `composition.py` 为真源，本表只列含义。

### 4.1 几何基础层（Frame）

保留现有指标：

| 指标 | 含义 |
|---|---|
| `headroom` | 头顶留白是否处于景别适用区间 |
| `lead_room` | 朝向前方是否有足够空间 |
| `rule_of_thirds` | 主体是否接近三分线交点 |
| `balance` | 多主体重心是否失衡 |
| `occlusion` | 关键主体是否被遮挡 |
| `framing` | 主体入画比例与预期景别是否匹配 |

新增：

| 指标 | 测量定义 | 硬门条件 |
|---|---|---|
| `edge_clearance` | 主体关键点（头、手、脚、道具）到画面边缘的最小安全距离 | 关键点完全出画 |
| `depth_separation` | 前后主体的深度差及其投影重叠率 | 主次主体深度不可辨 |
| `silhouette_separation` | 主体轮廓与背景/他人轮廓的分离程度 | 关键动作轮廓粘连 |
| `screen_size` | 主体屏幕高度/宽度与声明景别的偏差 | 主体尺寸与意图完全不符 |
| `horizon_stability` | 地平线倾斜、画面滚转和构图意图的匹配 | 无意图的严重倾斜 |

### 4.2 视线与注意力层（Frame/Shot）

| 指标 | 定义 |
|---|---|
| `gaze_target_visibility` | 视线目标是否在画内、是否被遮挡、是否落在合理前方区域 |
| `eyeline_consistency` | 同一对切镜头中人物视线高度、方向和目标关系是否连续 |
| `attention_priority` | 主体面积、位置、对比度、运动量与意图主体排序的一致性 |
| `focus_competition` | 非意图主体是否在面积/运动/对比度上抢夺注意力 |
| `beat_coverage` | 镜头是否覆盖该剧情节拍要求的主体、动作、结果信息 |

### 4.3 动作与因果层（Shot）

| 指标 | 定义 |
|---|---|
| `action_readability` | 动作起点、路径、终点或接触点在动作关键帧中是否可辨 |
| `cause_effect_visibility` | 发起者、受力者、动作结果是否形成可读因果链 |
| `contact_point_visibility` | 打击、抓取、碰撞等接触点是否在画内且没有被遮挡 |
| `pose_phase_separation` | 准备—发力—接触—反应四个阶段是否能区分 |
| `reaction_legibility` | 受击/被推动/失衡等结果姿态是否可见 |
| `prop_interaction_visibility` | 角色与关键道具的接触关系是否可辨 |

打斗镜头的默认硬门见 §5.2 H2。

### 4.4 连续性层（Sequence）

| 指标 | 定义 | 硬门条件 |
|---|---|---|
| `axis_continuity` | 相邻镜头是否保持 180 度轴侧及屏幕左右关系 | 未声明的越轴 |
| `motion_vector_continuity` | 角色/相机运动方向是否连续 | 追逐或打斗方向无意反转 |
| `scale_continuity` | 景别跳变是否有明确叙事意图 | 无意图的突兀跳级 |
| `eyeline_match` | 对切镜头视线目标和高度是否匹配 | 双方互看关系断裂 |
| `screen_direction` | 出画/入画方向、运动方向和剪辑承接是否一致 | 动作接续反向 |
| `temporal_readability` | 动作接触前后剪辑是否保留足够时空信息 | 结果先于动作且无法解释 |

### 4.5 摄影意图层（Shot）

| 指标 | 定义 |
|---|---|
| `perspective_fit` | 焦距、机位距离和主体关系是否符合景别/情绪意图 |
| `camera_path_clearance` | 运镜路径是否穿过角色、障碍或不可见区域 |
| `reveal_progression` | 建立镜头/揭示镜头是否在时间内逐步提供空间信息 |
| `movement_intent_match` | 推、拉、摇、移、跟拍等运镜是否服务于声明意图 |
| `spatial_orientation` | 环境地标、入口、出口、人物相对位置是否易于建立 |

### 4.6 鲁棒性与工程层（Shot）

| 指标 | 定义 |
|---|---|
| `pose_robustness` | 姿态轻微变化后各核心指标是否仍通过 |
| `camera_robustness` | 相机采样误差/轨迹插值后是否仍通过 |
| `label_safe_area` | 标签、网格、辅助线是否遮挡关键视觉信息 |
| `visibility_stability` | 关键主体在内容关键帧与动作关键帧中是否反复出画/被遮挡 |
| `repair_locality` | 修复是否只改变目标镜头/目标主体，未破坏其他镜头 |

## 5. 评分与门控

### 5.1 分层分数

每个分量输出 `0..1`，每层输出 `0..100`：

```text
geometry_score      = 几何基础层加权平均
attention_score     = 视线与注意力层加权平均
action_score        = 动作与因果层加权平均
continuity_score    = 连续性层加权平均
cinema_score        = 摄影意图层加权平均
robustness_score    = 鲁棒性与工程层加权平均
```

默认总览分只用于排序：

```text
overview_score = 0.25*geometry
               + 0.20*attention
               + 0.20*action
               + 0.15*continuity
               + 0.10*cinema
               + 0.10*robustness
```

默认值以 `specs/config.default.yaml` 为运行时真源，本表是规格快照；每次运行记录权重指纹。修复问题必须落在摆位、运镜或测量层面；改权重只用于实验对照，不作为修复手段。

### 5.2 硬门

以下任一条件成立，结论为 `fail`：

- **H1**：主体或剧情关键道具完全不可见；
- **H2**：打斗动作的攻击者、受击者或接触点不可辨；
- **H3**：未声明的轴线穿越；
- **H4**：关键视线目标完全不在画内；
- **H5**：相机路径穿过主体或环境碰撞体；
- **H6**：修复后目标镜头通过，但同一序列其他镜头被破坏且未记录。

### 5.3 严重度

- `fatal`：必须修复，不能只用 warning 通过。
- `error`：镜头不通过，但允许 agent 生成处方后复测。
- `warning`：不阻断交付，但进入报告和回归比较。
- `note`：仅记录设计信息。

## 6. 测量输入与证据

每个指标必须声明所需证据：

- 几何指标：相机投影、包围盒、深度、射线遮挡。
- 动作指标：动作关键帧、动作语义、接触点、速度向量、轮廓差分。
- 连续性指标：前后镜头的轴、屏幕方向、景别、相机轨迹。
- 意图指标：`IntentContract`、镜头类型、剧本节拍和角色关系。
- 鲁棒性指标：多帧采样、多姿态扰动、多相机扰动。

生产证据必须来自相机投影与场景状态；demo 输入必须标记 `evidence_grade=demo`。

## 7. Agent 交互契约

空间尺给 agent 的输入分三栏：

1. **事实读数**：当前值、目标区间、证据帧、置信度。
2. **方法卡**：检查顺序、优先级、判定规则。
3. **处方接口**：允许调用的工具、参数 schema、预期影响分量。

尺子提示只含事实读数、方法卡与处方接口三栏；正确工具名、参数值或“建议执行”文本一旦出现即判为污染，该任务不计入有效 agent 效果证据。

处方必须包含：

```json
{
  "component": "contact_point_visibility",
  "severity": "fatal",
  "current": 0.21,
  "target": {"min": 0.70},
  "allowed_tools": ["move_character", "move_camera"],
  "direction": "separate_subjects",
  "expected_effect": ["silhouette_separation", "action_readability"]
}
```

> 上面的 JSON 是目标契约；当前 `prescription.py` 是 demo 实现（字段 `component/current/target/tool/tool_args/note`），正式接入前必须收敛到本契约，见 §12 风险。

## 8. 场景覆盖矩阵

外挂评测集至少包含：

1. 单人标准中景：头顶留白、三分、入画比例。
2. 双人对话：视线留白、视线匹配、轴线连续。
3. 双人走位：前后景、深度分离、运动方向。
4. 打斗接触：攻击者/受击者/接触点/反应姿态。
5. 追逐：屏幕方向、速度向量、连续剪辑。
6. 多人群戏：注意力优先级、遮挡、层次和焦点竞争。
7. 建立镜头：环境揭示、尺度参照、空间定向。
8. 道具交互：手—道具—目标关系。
9. 特殊意图镜头：倾斜地平线、广角畸变、主观镜头。
10. 鲁棒性回归：姿态、相机和两类采样关键帧微扰。

每个场景至少提供 good、bad、ambiguous 三类样本；ambiguous 样本用于验证 agent 是否会请求人工复核，而不是强行给出确定结论。

## 9. 外挂 A/B 评测设计

四臂固定为：

- `baseline`：只有场景描述；
- `ruler`：场景描述 + 事实读数；
- `method`：场景描述 + 构图审核方法卡；
- `ruler_method`：事实读数 + 方法卡。

任务类型至少包括：`verdict`、`estimate`、`direction`、`fix`、`dynamic_facts`、`prescription_verdict`。

新增任务类型：

- `action_roles`：识别攻击者、受击者和结果；
- `continuity_verdict`：判断轴线/运动方向是否连续；
- `priority_order`：按修复优先级排序失败项；
- `robustness_verdict`：判断微扰后是否仍通过。

每条任务必须有纯几何或明确规则生成的 ground truth，不能由被测 agent 自己生成答案。

## 10. 报告格式

报告必须包含：

- 运行指纹：代码、指标 schema、权重、阈值、场景集版本；
- 每镜每帧原始测量值和证据引用；
- 六个层级分数；
- 硬门结果及触发原因；
- agent 回答、工具调用、处方接受/拒绝；
- bad → repaired 的分量变化；
- 未覆盖、低置信度和需要人工复核的项目；
- 四臂 delta 与置信区间（真实模型运行时）。

报告必须按指标列出提升、牺牲与相邻镜头破坏关系，至少回答：哪一个指标提升、是否牺牲了另一个指标、是否破坏了相邻镜头。

## 11. 验收标准

### 11.1 规格验收

- 所有指标定义、输入、阈值和严重度均有单一真源。
  - 验证：核对《空间尺指标规范 v1.0》与真源映射表，定义处只出现一次。
- 现有六项指标的历史样例结果不变。
  - 验证：`composition.py` 历史样例回归测试（pytest fixtures）全部通过。
- 每个新增指标至少有一组 good/bad/ambiguous 样例，与 §8 场景矩阵口径一致。
  - 验证：样例 fixtures 测试遍历每个指标的三态样例。
- 所有硬门都有反例测试。
  - 验证：H1–H6 各有一条触发与一条不触发测试。

### 11.2 外挂效果验收

- `ruler_method` 在 verdict、direction、fix、action_roles、continuity_verdict 五类任务上不低于 baseline。
  - 验证：外挂评测台运行四臂，比较 delta 与置信区间。
- 对打斗样例，动作与因果层必须单独报告，不并入总分。
  - 验证：打斗样例输出含动作层独立小节。
- 错误处方、不可执行工具和泄漏答案被拒绝。
  - 验证：负例集断言拒绝率，泄漏判词在报告中留痕。
- 相同输入、相同模型、相同版本重复运行结果可复现到规定容差。
  - 验证：重复运行两次，比对运行指纹与关键分数差。

### 11.3 真实效果声明

- mock 判官标记 `evidence_grade=plumbing`；真实模型 A/B 才支持“方法对 agent 有效”的结论。
  - 验证：结果标记校验；有效结论只出自真实模型 A/B 报告。
- Blender demo 证明测量—处方—复测链路可运行；agent 优化能力提升只由真实模型 A/B 单独证明。
  - 验证：demo 输出标记为链路证据，不进入有效性结论。

## 12. 风险与未决项

1. `action_readability` 和 `attention_priority` 需要动作语义与视觉证据结合，不能只靠几何。
2. “好构图”存在风格例外，硬门只应覆盖不可读和连续性破坏，不应覆盖所有审美偏好。
3. 多指标之间可能互相冲突，例如增加 lead room 会降低 balance；报告必须保留分量变化。
4. 新增指标接入前必须冻结 schema、阈值和样例，避免测试过程中漂移。
5. 当前 Blender demo 的人工 `SubjectBox` 只能作为演示输入；生产版本必须由实际相机投影和场景状态生成。
6. §7 处方 JSON 是目标契约，当前 `prescription.py` 是 demo 实现（字段 `component/current/target/tool/tool_args/note`）；正式接入外挂评测台前必须收敛到目标契约（`component/severity/current/target/allowed_tools/direction/expected_effect`），否则报告口径与契约不一致。
