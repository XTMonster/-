## 模型分工契约（Codex hooks 注入，效力等同 AGENTS.md）

### 0. 当前模型的定义（用户 2026-10-08 最新裁决）

用户原话：「不用deepseep了，就用当前模型」；
「对应hooks也把deepseek改成当前模型吧，这个当前模型是指当前选择的模型，不固定」。

**当前模型 = 当前会话选择的模型**，不固定为 DeepSeek、GPT-6A 或任何其他型号。
用户切换选择后，主线与新建子代理随当前选择执行；不能拿配置默认值、历史记录或
上轮选择覆盖本轮选择。hook 事件有 `model` 时以该字段记录本轮身份；
缺失时写“事件未提供，继承当前会话”，不猜型号。

- 主线执行、第一次修复：使用当前模型。
- 普通并行子代理：创建时**省略 `model`**，继承父会话；按不重复的角色分工。
- 用户明确指定独立评审型号时，才为该评审指定型号；通道不可用如实报错。
- 不为满足旧路由而修改全局 provider、切换默认模型、重启应用或另起固定型号进程。
- 历史里的“主线 DeepSeek”“执行只在 DeepSeek 上做”由本节替代。
  独立评审、产品内部模型、历史实验读数不因此被改名或改写。

### 1. 路由总则

| 工作类型 | 交给谁 | 交付物 |
| --- | --- | --- |
| 想法生成、质量审核 | 当前模型的角色子代理；需要既有联合会诊时，与 GLM-5.3 独立对拍 | 想法与依据；finding 带文件行号、命令和真实输出 |
| 难题攻关 | 先按修复阶梯定位；升级时加入 GLM-5.3，方案以其侧为主 | 可证伪方案、差异与执行步骤 |
| 人工裁决代理 | 既有 GLM-5.3 第三方通道；用户另点名才切换 | `reviewed_by: third-party`，真实型号、usage、理由 |
| 执行计划书写 | 既有 GLM-5.3 通道 `plan_writer --provider glm`；默认五轮精炼 | PRD、技术方案、TDD、执行顺序、出处及每轮 usage |
| 改代码、测试、构建、导出、提交 | **当前模型主线** | 真实产物、测试输出、提交 |

GLM-5.3 的专门职责保持不变；这是将原固定执行角色改为动态继承，
不是取消独立审核。若用户当轮另要求只用当前模型，按当轮要求做角色独立审查，
如实标为同模型审查，不冒充跨模型或跨族共识。

### 2. 联合会诊与身份留证

1. 两侧读同一份源码包、相同角色提示。先落 bundle/manifest，逐字源码带行号。
2. 记录 `both / severity_conflict / glm_only / main_only` 四栏及两侧真实型号；
   一侧缺席、空正文、超时或未解析永远不算同意。
3. `tools/panel_consult.py` 的旧 `deepseek` 槽位不是“当前模型”的别名。
   当前模型非 DeepSeek 时，不为运行旧工具而调用 DeepSeek，也不把当前模型
   判词伪装为 DeepSeek。可由当前模型主线留自己的判词，再用
   `tools/glm_consult.py --roles <角色> --question <问题> --source <文件:起-止>
   --out <证据目录> --level low` 对同包取 GLM 判词，逐条对拍并保留真实身份。
4. 当前模型本来就是 GLM 同族时，两次调用不算跨族复核。确需跨族的验收仍需
   具名独立通道；不能用角色数代替模型族数。
5. GLM 型号仍为 `glm-5.3`；小包约 2k token。外部 relay 仅用户显式点名时使用。
   用户在客户端选中某模型即可让该模型执行，不等于要求另起该型号的会诊 API。
6. 判词不是测试结果或测量证据；不改判据、阈值、分母，不伪称 `human`。
   产品内部 E1 评委、重排器、抽取族和冻结证书的身份规则原样保留。

### 3. 主线与子代理纪律

- 审查前全量盘点相关现状、文件与资料；先想法和审核，再改代码。
- 子代理声明唯一角色：规格、契约、测试、性能、安全、文档等，不重复视角。
- 结论格式：角色 → 结论 → 证据 → 缺口与风险 → 可执行动作；未验证明确标注。
- 主线逐条证实或证伪判词，逐阶段新增并运行有效测试，失败先修，不跳步。
- 汇报区分独立通道的判词与当前模型的执行结果；不能虚构模型名、usage 或共识。

### 4. 修复阶梯

同一个问题沿用 `repair-key: <slug>`：第一次由**当前模型主线**定位并修复；
第二次加入 GLM-5.3（low）；第三次及以后加入 GLM-5.3（high）。
外部 relay 不自动启用。修复后用 `repair-key: <slug> done` 复位。
每级留命令、真实输出和可用的 usage；三级仍失败则如实报阻塞，不降级绕过。

### 5. 历史与边界

旧通道实测、接入命令、用户旧原话见同目录 `model-routing-history.md`，
仅在查历史问题时读取；**历史不是当前路由命令**。用户选择不会被“用完还原”
之类旧的临时切换流程自动覆盖。未经要求不修改 `config.toml` / `hooks.json`，
不重启应用；不为绕超时降低当前选择的推理强度。
