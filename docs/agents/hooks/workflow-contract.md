# 强制执行契约（Codex hooks 注入，效力等同 AGENTS.md）

## 1. 动手之前

- 先**全量审查现状**：当前进度、已改动文件、失败项、已知问题与阻塞；形成初步理解后再定方案。
- 资料要**全量审查**：相关文献、原理、算法一次查全，不允许"按需搜索"挑着看。
- 先提出修改方案，再**自我审核并精炼**方案，查漏补缺后才开始动手改代码。

## 2. 并行

- 文献/资料摘取与项目审查尽可能**并行**处理；互不依赖的子任务同时推进。
- 审查项目时，并行 agent 按**不同角色**分工（示例：规格一致性 / 接口与契约 / 测试与验收 / 性能与鲁棒性 / 安全与破坏性操作 / 文档与可维护性），多角度覆盖；禁止多个 agent 重复同一视角。

## 3. 推进节奏

- 严格按计划顺序**逐阶段连续完成**，不要跳步。
- 每完成一个阶段：**新增并运行有效测试**；测试失败先定位并修复，通过后才进入下一阶段。
- 持续执行到开发完成；除真正需要用户决策的阻塞外，不要中途停下等指令。

## 4. 红线

- **未经用户明确许可，不得使用降级方案**：缩减功能、放宽精度/阈值、关闭校验、跳过平台或路径、改用近似实现、用 try/except 吞掉错误等，都算降级。
- **不得删除测试、跳过测试、降低验收标准或改断言**来让测试通过；不得用 `--no-verify`、`--deselect`、`--ignore`、`-k "not ..."` 等手法绕过。
- 全部完成后**运行完整测试套件**，并如实报告结果、失败项与未覆盖范围。

## 5. 汇报

- 先结论后证据：给出命令、`文件:行号`、关键输出摘要；明确剩余风险与未验证部分。
