## 二、门⑩ 的根因：不是标注质量问题，是"期望超定"

4558 条未解析 spec 拆开看：

1. **1416 条指向幽灵卡 id**（`gen_anime_0001..0072`、`gen_axis_0001..0056`）。
   语料换血时卡 id 重发（`tools/kb_fetch/import_cards.py::_finalise` 按身份补号，
   身份含正文 sha256），旧 id 不复存在 → 这些条目整体作废。
2. 其余 3142 条（卡仍在语料里）的"落地度"：
   - 与**该卡自身抽取原子边**成员集完全吻合的：**26 条**；
   - 卡片正文里出现全部期望取值的：**0 条**。
   → 标注员的 `must` 不是从卡里抽出来的，是**编出来的**（`q` 与边都是）。
3. 供给侧：891 条归并边、2843 条原子边、2113 张卡 → **1.35 原子边/卡**；
   而 oracle 要求 4239 条 × 平均 2 个 `must` ≈ **8500 条期望**。
   **期望空间大约是语料真实知识量的 3 倍**。

结论：门⑩ 在"标注方不可见索引 ＋ 期望超定"两条同时成立时**结构性不可达**；
而门⑧（换族）禁止"机械从索引派生 oracle"绕过 —— 那等于自己考自己。

## 三、取舍：候选池标注（TREC pooling 的标准做法）

**新通道**：标注方看到的是**本卡自己的原子边候选池**（≤12 条），从池里挑
`must`／`top1`，自己写 `q`，并从池里挑 `never`。产出侧强制：

* 门⑨：`q` 必须覆盖 `must[0]`／`top1` 的全部可查询槽位；
* 门⑩：`must`／`top1`／`never` 的每一条都必须能 `spec_to_norm_key()` 解析到当前索引。

**这一改动的代价（必须写明）**：
* 新 oracle 测的是**排序质量**（"该召回的边有没有排在前面"），**不再**测
  "索引漏没漏知识"（抽取召回）；
* 抽取召回改由两条独立证据承担：(a) 自由标注口径的**覆盖率**（旧 oracle 保留，
  按 `subset` 关系汇报）、(b) `docs/knowledge/EDGE_REVIEW_SAMPLE.md` 的人工边审。

**收益**：Q1/Q2/Q4/Q6b 从"分母里塞满不存在的边、算出来没有意义"变成可测；
门⑨ 由构造保证 100%，门⑩ 由构造保证（残余由 `spec_to_norm_key` 逐条拦）。

## 四、协议 §5.2 的收窄边界（可复核清单）

| 项 | 旧通道 | 新通道 |
|---|---|---|
| 归并后的索引 | 不可见 | **不可见** |
| 检索器 / `knowledge_trace.json` | 不可见 | **不可见** |
| 抽取 prompt | 不可见 | **不可见** |
| 本卡自己的**原子边候选池** | 不可见 | **可见**（这是唯一放宽项） |
| 本卡正文 / 冻结词表 / schema | 可见 | 可见 |

放宽的理由：门⑩ 要求"期望边必须存在于索引"，而标注方看不到索引就无法保证，
两条判据在构造上互斥（§二的三条数字）。放宽只到"看见本卡自己的原子事实"，
不足以让标注方复述检索器行为（它看不到归并结果、看不到排序、看不到别的卡）。

## 五、Q4 = 1.0 的结构性天花板（决定生成口径）

`Q4` 要求**每一条 `required` 边**都落进 top-3，所以 `q` 必须能唯一区分目标边。
实测（`q` 含该边 `forbid_*` 取值时）：

| (type, q) 组大小 | 组数 | 覆盖边数 |
|---|---|---|
| 1 | 527 | 527 |
| 2 | 162 | 324 |
| 3 | 9 | 27 |
| 4 | 2 | 8 |
| 5 | 1 | 5 |

**878/891 条边所在的组 ≤3，可全部落进 top-3**；剩 13 条（3 个组）在构造上
无法满足 Q4，按 skip 计入报告，不编造查询。逐类可覆盖的卡数最低的是
`EDIT_RHYTHM`（4 张卡）——门④ 的"每类 ≥30 对、≥10 张卡"对它是硬缺口，
必须如实报，不得用重复 `q` 凑数。

## 六、连带修掉的两个索引侧死角（提交 a359d53）

1. **同 kind 多值边**（31 条）：跨卡归并把同一槽位的多个取值塞进同一条边
   （`composition_rule=lead_room,composition_rule=rule`），而 oracle 规格语法
   每个 kind 只能写一个值（`parse_spec` 用 dict 收，后者覆盖前者）→ 结构性未解析。
   修法：备选值各自复制一条边（`manifest.merge.alternatives` 计数）。
2. **同 kind 同时 allow+forbid 被误判为自相矛盾**（8 条）：
   `movement=crane_up` + `forbid_movement=dolly_out` 不冲突（取值不同），
   旧判据是 kind 级的。改为取值级。

整库守卫 `tests/test_check_holdout.py::test_every_index_edge_can_be_written_as_a_spec`：
任何边写不成规格即失败。
