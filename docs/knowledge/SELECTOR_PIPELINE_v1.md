## 步骤 0（**本轮新发现的硬前提**）：现有产物**装不下**选择器的评估

`docs/evidence/20261006-e1-triple-ceiling/full_search.json` 的键只有
`best_per_query / distribution / E1_best_of_search / triples_judged …` ——
**每条查询只留了"最好的那一组"**，**1,280 个三元组里其余 1,216 个的标签没有落盘**。

⇒ **没有它就没法给选择器打分**（无法回答"它挑的那组"与"最好那组"差多少）。

**要做三件**：① 扩 `tools/knowledge/e1_triple_search.py`，把**每一个被判过的三元组**
（查询、三个 case_id、逐行分数、命中数）写进产物；② 它**是冻结仪器**（第二十次冻结）
⇒ 扩完要**单独提交一次重新冻结**并写理由（与第二十/二十一次同规）；③ **重跑一次**
（同参数约 **1h50m**，上一次 18:58→20:48 就是这个量级）。

## 步骤 1：候选池必须**去标签**（否则选择器学到的是"答案"）

现在那 20 组是**按标签分取 top-6 再全组合**得到的 ⇒ **池子本身就是标签的产物**。
裁定要的是"预测每组的相关条数"——池子可用标签挑，选择器**不许**用。

⇒ 建立**去标签池**：按**产品检索器**的原始名次取前 6（或用一个**不看判分**的重排器）再全组合。
这一步会把 oracle 的数值**往下拉**（池子更差），**必须重算**，不许拿 0.7448 当新池子的上界。

## 步骤 2：训练集**另取查询**（裁定原话）

| | 现状 | 够不够 |
|---|---|---|
| 训练查询 | `docs/evidence/20261006-unseen192/reviews.unseen192.*.jsonl`：**192 条未见查询**，`judge_batch=3`，**每条 1 组**三元组 | **薄**：选择器要学的是"**同一查询内哪一组更好**"，而这里每条查询只有 1 组 ⇒ **学不到排序** |
| 评测查询 | 那 64 条（裁定定名：**固定集回归验收**） | 够，但**不能再当留出集** |

⇒ **要新产一批训练数据**：取与 64 条**不相交**的查询（例如从 192 条里取 64 条），
每条生成 **20 组**三元组并按 **C=3 语境**判分。成本与上次同量级（≈1h50m，2 位评委）。

## 步骤 3：特征（**一律不碰判分结果**）

每条 case：池内名次、检索分数、线索 `zh` 有无/长度、查询与线索的**词面重叠**、摘录长度。
每组三元组：以上三项的 mean/min/max、**线索覆盖率**（3 条里有几条有线索）。
（可选，仍不许看判分：标签无关的 LLM/嵌入打分。）

**明令排除**：任何来自 C=3 判分的量（`score`/`hits`/评委分）——那就是 oracle 本身。

## 步骤 4：模型与评估（先小、可证伪）

先做**线性打分**（三项均值 → 预测 0..3），训练集＝步骤 2 的新数据，评估集＝那 64 条固定集。
报告三个数并排：**选择器 E1 / 去标签池的 oracle / 现役交付的 0.1771**，以及线 0.70。
**不许**把"训练集上的分"当成绩；**不许**跨运行拼接。

## 步骤 5：正式跑（裁定要求的形态）

冻结实现/模型/参数 → **预先登记** → 跑满 64 条 → **评分前封存交付的三条** →
同两位评委按 C=3 判 → 判据 **≥135/192**。证据必须**绑当前代产物**（指纹/digest）。

## 现在缺什么（一句话）

**缺的是"每一个三元组的标签"和"一批属于别的查询的训练数据"**——两样都要**跑**，
而现有的 1,280 次判分结果**只留了每组的最好那一组**，所以**步骤 0 必须先做**。
