# ADR-0016 严格构图质量契约与单一真源

状态：Accepted（2026-10-21）

取代：[ADR-0012](0012-composition-gate-and-assertion-hygiene.md) 中构图门
`>= 70.0` 的阈值与比较口径；ADR-0012 的“主体几乎出画时封顶 20 分”和
“禁止恒真断言”仍然有效。

## 背景

历史实现曾把构图门写作 `>= 70.0`，随后用户裁决：构图总分必须严格高于
`80.0`。代码虽已在多处执行严格比较，但粗排、细排、driver、空间尺观测和
交付层仍各自持有比较语句，部分文案只写“80 分门槛”或旧 `>= 70`，导致：

- `79.99`、`80.0`、`80.01` 在理论边界之外可能因入口不同而产生不同解释；
- `NaN` 或无限值可能被局部比较静默吞掉；
- 新增消费者容易再次复制阈值；
- 坏质量结果没有统一的反序列化/校验边界。

## 决策

1. `block_director/contracts/quality.py` 是所有构图总分判定的唯一真源。
2. 默认门槛固定为 `80.0`，通过条件固定为 `score > 80.0`：
   - `79.99` -> `fail`
   - `80.0` -> `fail`
   - `80.01` -> `pass`
3. 未测量或非有限分数显式失败；只有“已声明空镜且存在空镜证据”可返回
   `exempt`，缺证据返回具名 `blocked`。
4. 生产消费者不得复制阈值比较，只能调用契约判定。兼容层可以转发，但不得
   再实现第二套语义。
5. 质量结果带 `quality-contract/v1` 版本、封闭状态集
   `pass/fail/blocked/exempt`，并通过稳定 JSON 序列化与结构校验。
6. 构图分项的处方目标同样使用数学开区间：`0.8` 必须继续修复，
   `0.8001` 才进入目标。开闭端点是 `TargetInterval` 的显式字段，不用
   epsilon、下一可表示浮点数或文案提示伪造严格边界。

## 后果

- 粗排、细排、driver、React 触发、空间尺观测和交付失败判定必须对同一组
  三边界输入给出相同结论；
- `80.0` 永远进入修复或失败路径，不能仅因为舍入而通过；
- 历史证据保留原样，但旧 `>= 70` 或 `80.0 => pass` 的读数不得作为当前代码
  的验收证据；
- 契约校验失败必须向上报错，不能用 `except` 吞掉并当作通过。

## 验证

- `tests/test_quality_contract.py` 固定底层三边界与空镜/缺测语义；
- `tests/test_quality_contract_consumers.py` 固定粗排、细排、driver 计划分、
  React 触发和交付文案对同一三边界的一致性；
- `tests/test_ruler_observation_build.py` 固定空间尺观测的三边界；
- 空断言扫描、配置规格检查和全量 pytest 必须通过。
