# Blender 白模预演 → AI 视频参考：痛点调研与项目功能评估

> 面向场景：LLM 驱动的 Blender 白模预演插件（生成剧本/分镜 → 搭建白模场景与相机 → 导出参考视频 → 喂给 Seedance 2.5 / Hailuo H3 等视频模型出片）。本文是《白模预演构图数据校验_深度调研报告》的续篇：上一篇论证"数据层构图校验"的可行性，本篇调研**整条白模参考工作流在实际使用中暴露的痛点与难用之处**，逐项评估项目能否解决、需要在当前架构上加什么。

## TL;DR

调研得到的痛点分三层：**模型侧**（视频模型如何"误读"白模参考——把灰盒当外观来源、相机反向、比例漂移、一镜多运动丢失、参考预算超限）、**制作侧**（Blender 学习曲线、相机手感机械、视口导出的设置地狱、白模质量吃输入图）、**衔接侧**（时长/宽高比/帧率与目标模型不匹配、参考角色提示词缺失、跨镜头一致性断裂）。结论是：**约六成痛点可以在数据层或导出层由项目直接解决**，且大多与已规划的几何校验层同构——校验层从"查构图错误"自然扩展为"查参考视频对目标模型的适配性"；约两成靠导出时固化"参考分工提示词模板"的流程设计解决；剩余两成（动作细节、表情演技、成片一致性返修）属于白模参考路线的固有边界，项目该做的不是硬解，而是**在剧本层显式声明分工边界，防止 LLM 把不该白模承担的任务塞进白模**。

## 1. 调研范围与证据来源

本轮调研覆盖三类证据：

- **官方/平台文档**：Seedance 2.5 提示词指南（火山引擎 Ark 文档）明确了白模参考的输入规范与素材预算上限；Kling、Hailuo H3 的 API 与第三方整理给出了时长、参考数量的硬约束。
- **一线实测报道**：updream 预演台的多组对照实测（ifanr、BAAI、新浪、163 等），直接记录了"无白模 vs 有白模"的差异与白模侧返工的位置；GPTunneL、ArcLoop、Higgsfield、Mixar 等同类工具的工作流文档，记录了大量"这条管线在哪里会断"的第一手经验。
- **Blender 社区与工具生态**：视口导出类插件（Render Viewport）的存在本身即痛点证据；相机抖动插件（Camera Shakify）印证了"机械感运镜"问题；相机路径动画的失控/翻转是社区高频问题。

## 2. 痛点清单：白模参考工作流在哪里会断

### 2.1 模型侧：视频模型如何"误读"白模参考

这是返工成本最高的一层——错误不在 Blender 里，要烧一次生成积分才暴露。

**P1 白模被当作"外观来源"而非"空间参考"。** 把白模视频不加说明地丢给视频模型，模型会把它当 video-to-video 任务处理："美化"这些盒子、加上材质，返回的还是一条盒子视频。GPTunneL 为此在节点里内置了第二个输出 `prompt`——一段调试好的角色分工指令："只从参考视频取运镜、镜头切换、节奏与物体摆放，把每个几何体当作描述中真实物体的占位符，几何体颜色不代表物体颜色"，并特别注明"长长的禁止清单不如简短的正向指令有效"。Seedance 2.5 官方也配套了白模提示词规范。这意味着**白模视频本身不是完整交付物，"白模 + 分工提示词"才是**。

**P2 灰色污染与风格欠锚。** 即使模型理解了参考角色，灰盒画面的色调仍会渗透进成片——ArcLoop 明确记录了"灰盒静帧会把生成拉向灰色"的失败模式，对策是风格参考图与场景主图锁死视觉方向，白模静帧只作构图参考。实测报道同样指出：参考图太单薄、只靠一行风格文字时，成片会"泛 generic"。

**P3 相机反向与走位镜像。** ArcLoop 列为最高频失败："预演里镜头从左往右跟拍，成片从右往左"——原因是运镜方向只存在于画面里、没写进文字，模型对参考的解读存在镜像自由度。对策是镜头卡片里必须**用文字拼出运镜的起止**（"start position, move, end position"），不能仅靠参考视频。

**P4 一个镜头塞两个运动，必丢一个。** "镜头先下潜再拉远"这类复合运镜，模型大概率只执行其一——对策是拆镜头。这是白模内容设计层面的约束：单镜头的运动复杂度有上限。

**P5 比例漂移从白模传导到成片。** "预演里做高了的胶囊体，在成片里变成巨人"——视频模型忠实放大白模中的比例错误，且**必须在白模侧修，提示词修不回来**。这条直接验证了上一篇报告的核心论点：参考视频的几何正确性决定下游成片质量。

**P6 白模粒度悖论：太粗不够，太细有害。** Seedance 官方建议白模用"简单几何体拼接"的粗粒度；ifanr 实测发现打斗镜头要"刻意减少白模承担的动作细节"——挥拳怎么挥、格挡什么姿态属于模型该自由发挥的部分，白模管的是整体位置与机位路线。粗粒度白模适合"这个人从这里移动到那里"，细微动作交给 Prompt 和人物参考图。粒度拿捏错误（白模里 K 了僵硬的手部关键帧）反而污染生成。

**P7 参考素材预算与时长硬顶。** Seedance 2.5：单段最长 30 秒，视频类参考最多 10 段且总时长 ≤30 秒，主体参考视频建议 5–10 秒（更长则稳定性下降需要抽卡）；Kling 单次生成只有 5/10 秒两档，延长链总顶 3 分钟且 30 秒后质量退化；Hailuo H3 单段 4–15 秒、参考上限 12 个文件（9 图 + 3 视频 + 3 音频）。**同一条预演时间线，喂给不同模型需要不同的切片方案**；延长/续写还会"继承漂移"，必须先锁定满意版本再延展。

**P8 跨镜头一致性只能缓解、不能根除。** updream 实测确认白模大幅改善了多机位间的空间连续性（四个镜头切换点最大误差不到一帧），但角色外观一致性垮掉、物理细节错误仍需靠局部重绘/逐镜返修；行业分析也指出"参考帧、embedding、约束必须跨步骤显式传递，否则连续性必丢"。

### 2.2 制作侧：Blender 白模本身的操作痛点

**P9 学习曲线是最大的显性门槛。** "几个月起步的 Blender 学习成本"是 updream 预演台这类产品的立身之本——它们的存在本身就是痛点证据。替代路径（ComfyUI + ControlNet 搭节点、让 coding agent 写 Three.js）门槛同样不低，且"调一版运镜要改参数重渲，来回折腾"。对本项目而言这层痛点已被"LLM 生成场景"绕过，但**绕过的代价是 LLM 的操作失误率**——正是上一篇报告构图校验层要兜的底。

**P10 相机运动的机械感与参数失控。** 两个方向的问题并存：一是纯关键帧插值的运镜"过于完美和机械"，缺手持呼吸感（Camera Shakify 插件的存在意义）；二是路径跟随类动画的高频翻车——Follow Path 的曲线扭曲导致相机不可控翻转、速度失控需手动调偏移因子。LLM 生成相机动画时这两类错误都会犯，且它"看不见"翻转结果。

**P11 视口导出的"设置地狱"。** Blender 导出一条视口预览 mp4 要动八九项设置：输出路径、格式、容器、编码、质量、分辨率百分比，切到视频格式还会**静默丢弃 PNG 序列的 alpha 通道与 16 位色深且切回不恢复**（Render Viewport 插件专门解决这个，备份-渲染-还原要动 9 项设置）；Blender 还会给文件名自动追加帧范围后缀。对人工用户是繁琐，对 LLM 自动管线是**确定性陷阱**——任何一项状态残留都会污染后续正式渲染。

**P12 白模质量吃输入。** 从参考图生成白模的路线（updream 等），输入图透视歪则白模跟着歪；手动搭则回到 P9。本项目的 LLM 直接生成几何，不吃这条亏，但等价风险换成了**白模包围盒代表性**（上一篇 §5 已述：胶囊体缺头发/武器/飘带轮廓）。

### 2.3 衔接侧：预演产物与目标模型的规格错配

**P13 时长/宽高比/帧率错配。** 白模时间线按创作意图设计，但下游有硬规格：Seedance 2.5 输出宽高比自由但限于 [0.4, 2.5] 区间、靠输入素材控制；单段 30 秒封顶；Kling 只有 5/10 秒粒度。预演做了 45 秒一镜到底，喂之前才发现要切——切片点选不好还会破坏运镜完整性。

**P14 提示词职责冲突。** 实测经验：白模到位后提示词"不用费劲描述镜头运动和站位"，只写素材职责、人物设定、场景氛围与按时间线的动作台词；反之若提示词与白模各说各话（文字说一套、白模演一套），模型会在两套指令间摇摆。"素材职责冲突时先减素材，不要继续堆叠参考"。

**P15 迭代回路的位置错误。** 新手高频错误是"试图用提示词挽救弱机位"——相机和构图属于 Blender，该回白模里修再重新导出，而不是在下游加文字补丁。 Porto 的实测把"在错误层修问题"列为三大弯路之首。其次是"把白模当一次性耗材"：白模现在是**生产资产**，十分钟的几何打磨换回的是更少的重抽。

**P16 不适用场景误用。** 固定机位口播、简单静物、单人不动镜头开白模是浪费；光影本身是全部内容的镜头（剪影横移、光线扫过）给白模反而多此一举——视频模型本来就能做好，白模约束只会限制发挥。

## 3. 逐项评估：能不能解决、在哪层解决、项目要加什么

将 16 项痛点对照当前项目架构（LLM 场景生成 + 数据层构图校验层 + 告警裁决回路 + 导出）逐项评估。判定分三档：✅ 项目可直接解决（数据层/导出层确定性处理）；⚠️ 项目可大幅缓解（流程设计 + LLM 裁决配合）；❌ 白模路线固有边界，项目应做边界声明而非硬解。

| # | 痛点 | 判定 | 解决层 | 项目需要新增/扩展 |
|---|---|---|---|---|
| P1 | 白模被当外观来源 | ✅ | 导出层 | **参考分工提示词模板引擎**：导出白模视频时自动生成配套指令（"只取运镜/走位/时机，几何体是占位符"），按目标模型（Seedance 2.5 / Hailuo H3）切换模板——GPTunneL 已验证正向短指令优于禁止长清单 |
| P2 | 灰色污染、风格欠锚 | ⚠️ | 导出层 + 剧本层 | 导出清单检查：白模视频之外是否配齐角色参考图/风格图；白模导出**强制灰底中性色 + 无风格化**，并在配套提示词中显式声明"白模颜色不代表最终色调" |
| P3 | 相机反向/走位镜像 | ✅ | 数据层 + 导出层 | **运镜文字化器**：从相机曲线自动提取"起点方位→运动方向→终点方位"生成自然语言描述，写入镜头卡片。几何信息项目里全有，纯数据层计算，且与校验层共用采样管线 |
| P4 | 一镜多运动必丢 | ✅ | 数据层（校验层扩展） | **单镜运动复杂度检测**：统计镜头内相机速度方向突变次数 + 主体运动事件数，超过阈值（如 ≥2 个复合运动）告警"建议拆镜头"。时间线事件检测的自然扩展 |
| P5 | 比例漂移到成片 | ✅ | 数据层（校验层扩展） | **比例一致性校验**：人物胶囊体高度 vs 场景参照物（门、桌椅、楼层）的比例是否在合理带；同一角色跨镜头包围盒世界高度是否一致。白模侧修比例是唯一正解，必须拦在导出前 |
| P6 | 白模粒度悖论 | ⚠️ | 剧本层 + 校验层 | **粒度守则**：插件默认只生成粗粒度几何（官方建议即如此）；校验层反向检测"白模过度细节"（如手部细小关键帧、表情骨架），告警"该细节应移交 Prompt/参考图" |
| P7 | 参考预算与时长硬顶 | ✅ | 数据层 + 导出层 | **目标模型适配器**：内置各模型规格表（单段时长、视频参考总时长/段数、宽高比区间、建议参考时长），时间线超限时自动建议切片点（优先选镜头切换处、运镜静止段），并按切片批量导出 |
| P8 | 跨镜头一致性残余 | ⚠️ | 数据层 + 导出层 | 已有 cut 级校验（轴线/跳切/站位连续性）之外，导出**跨镜头 continuity 表**（谁在画面哪侧、朝向、相对位置）随参考包一起给下游；成片端残余问题靠模型局部编辑能力返修，项目边界外 |
| P9 | Blender 学习曲线 | ✅ | 已被架构解决 | LLM 生成场景本身即答案；需守住的是上一篇的构图校验层，兜住 LLM 的操作失误 |
| P10 | 运镜机械感/路径失控 | ✅ | 数据层 + 生成层 | 生成层：可选手持抖动预设（噪声修改器）与缓动曲线模板；校验层：**相机翻转检测**（up 向量逐帧符号突变）与**速度曲线检测**（加速度超阈值告警）——纯时间线几何计算 |
| P11 | 视口导出设置地狱 | ✅ | 导出层 | **一键导出沙箱**：导出函数内完整备份/还原全部输出设置（格式、编码、路径、色深、分辨率比例），强制相机视角、锁帧率、文件命名规范化；LLM 永不直接接触全局渲染设置 |
| P12 | 白模质量吃输入 | ✅ | 已被架构解决 | LLM 直建几何不吃参考图歪斜的亏；对应风险（包围盒代表性）已在上一篇 §5 用安全边距 + 置信度标注覆盖 |
| P13 | 规格错配 | ✅ | 数据层 | 与 P7 同一适配器：建项目时选定目标模型，场景帧率/宽高比/单镜时长**在建场时即按目标规格初始化**，而非导出时才发现 |
| P14 | 提示词职责冲突 | ⚠️ | 导出层 + 剧本层 | 导出包生成**职责分离的提示词骨架**：白模管什么、角色图管什么、文字管什么分区填写；校验层检测文字提示词中的运镜/站位描述是否与白模实测矛盾（如文字写"从左向右"而相机实测从右向左），矛盾即告警 |
| P15 | 在错误的层修问题 | ⚠️ | 回路设计 | 裁决回路增加一条元规则：构图/运镜类问题一律回 Blender 侧改参数重导，**禁止用下游提示词补丁绕过几何问题**；告警报文的 suggestion_hint 只给 Blender 侧的修改建议（如"shift_x +0.02"），不给提示词话术 |
| P16 | 不适用场景误用 | ⚠️ | 剧本层 | LLM 分镜规划时的前置判断：固定口播/静物/纯光影镜头标记为"跳过白模，直出提示词+参考图"；避免为每条镜头机械套白模流程 |

### 统计

✅ 直接可解 9 项（P1、P3、P4、P5、P7、P9、P10、P11、P12、P13 中除剧本配合外的主体部分），⚠️ 可缓解 5 项（P2、P6、P8、P14、P15、P16 中需 LLM 配合的部分），真正不可解的硬性边界只有一条共性：**白模管不住动作细节、表情演技与最终画质**（P6/P8 的残余部分）——这是参考粒度的理论上限，不是工程缺陷。

## 4. 当前项目需要加什么：功能模块清单

结合上一篇报告的四期路线图（单帧 MVP → 时间线 → 遮挡与镜头间 → 混合复核），本次调研要求新增五个模块，并按依赖关系插入路线：

**M1 导出包生成器（最高优先级，插入第一期）。** 白模视频只是半成品，完整交付物是"参考包"：白模视频 + 目标模型适配的分工提示词（P1）+ 逐镜头运镜文字描述（P3）+ 跨镜头 continuity 表（P8）+ 职责分离的提示词骨架（P14）。这是本调研发现的**最大空位**——现有工具里只有 GPTunneL 做了内置提示词输出，而它是闭源节点；Mixar 做了"beauty/clay/depth 三通道导出"也值得借鉴（clay 通道抑制材质只留形体光影，depth 通道给 ControlNet 类管线备用）。

**M2 目标模型适配器（第一期）。** 模型规格表（时长/宽高比/参考预算/建议粒度）+ 建场初始化（P13）+ 超限切片建议（P7）。规格表要做成可更新的数据文件而非硬编码——模型迭代极快，Seedance 2.0→2.5 的参考预算就从 15 份涨到 50 份。

**M3 导出沙箱（第一期）。** 一键导出参考视频，设置全备份全还原，锁相机视角/帧率/命名（P11）。同时输出可选的 depth 通道（白模场景渲染深度图成本趋零，给 ControlNet 类工作流留接口）。

**M4 校验层三项扩展（并入第二、三期）。** 比例一致性校验（P5，第二期）、单镜运动复杂度与相机翻转/速度检测（P4、P10，第二期）、提示词-白模矛盾检测（P14，第三期，需文本比对，是唯一涉及语义判断的项，可交给 LLM 裁决层执行，校验层只负责提供实测方位数据）。

**M5 剧本层分工声明（第三期）。** 每镜头标注白模职责边界（P6、P16）：哪些交给白模（位置/机位/节奏）、哪些移交 Prompt（动作细节/表情/情绪）、哪些移交参考图（外观/风格）、哪些镜头跳过白模。这份声明同时是校验层的比对依据（上一篇"声明 vs 实测"机制的复用）和导出包的组成部分。

### 更新后的优先级矩阵

| 优先级 | 模块 | 理由 |
|---|---|---|
| P0（本周） | M1 导出包生成器（最小版：白模视频 + 分工提示词模板） | 不做这个，白模视频喂下去大概率返回"美化版盒子"，整条管线空转 |
| P0 | M3 导出沙箱 | 一天工作量，消灭一整类静默状态污染 |
| P1 | M2 目标模型适配器 | 防止"做完才发现要切片"的返工 |
| P1 | M4-a 比例一致性校验 | P5 是实测确认的高频传导错误，且计算简单 |
| P2 | M4-b 运动复杂度/翻转/速度检测 | 依赖时间线采样管线（第二期） |
| P2 | M5 剧本层分工声明 | 依赖景别声明机制，与第二期的"声明 vs 实测"同步落地 |
| P3 | M4-c 提示词-白模矛盾检测 | 依赖 LLM 裁决层成熟后接入 |

## 5. 边界声明：调研确认的三条"不要硬解"

1. **动作细节与演技不归白模管。** 打斗招式、格挡姿态、微表情属于视频模型的发挥空间，白模里 K 细粒度动作反而有害（P6）。项目的正确动作是在剧本层声明移交，而不是增强白模动画能力。
2. **成片端的残余不一致靠下游能力。** 角色外观跨镜漂移、物理细节错误，即便白模完美也会出现，靠模型的局部编辑/时间戳编辑返修（Seedance 2.5 已支持）。项目导出 continuity 表是尽人事，此后是模型能力边界。
3. **不要把白模流程强加给不需要的镜头。** 纯光影镜头、固定口播用白模是负优化（P16）。校验层和剧本层都应把"该跳过白模"当作合法分支，避免指标驱动的过度使用。

## 6. 结语

本轮调研最重要的发现是：**"白模参考"这条管线的故障点正在从"生成质量"向"交接质量"迁移**。模型侧（Seedance 2.5、Hailuo H3 这一代）对白模参考的理解已经相当可靠——实测里多机位切换点误差不到一帧、一次直出不抽卡的案例已不罕见；真正烧钱的错误集中在三处交接面：白模视频的"身份声明"（P1/P2：它是空间参考而非外观来源）、预演规格与模型规格的匹配（P7/P13）、以及白模几何错误向下游的忠实传导（P5）。这三处恰好都是确定性问题，与项目已有的数据层校验同构——换言之，本次调研要求新增的模块大部分是**已有校验层架构的自然延伸**，而非新架构。建议以 M1（导出包生成器）为下一个里程碑：它是调研中发现的竞品空位最大、实现成本最低、不做则管线不闭环的一项。
