feat(P12-part3): separate overlapping labels and pin their layout

BW-2 (SS5 P12, third slice).

- label_baking.bake_labels is now frame-major: for each sample frame it first
  computes every label's landing point (out-of-frame push-back, occlusion
  lift), then runs a label-vs-label separation pass, and only then writes the
  keyframes. The old shape ("compute one label, write it, move to the next")
  had nobody to yield to when two labels landed on top of each other.
- separate_labels(): screen-space AABB overlap (area(A∩B)/min(area(A),area(B)))
  is driven under 5% by lifting the upper label, with the displacement capped
  at 0.25 x frame height (RK-2's band) and a bounded iteration count. Each
  label now carries offset_reason ("none" / out_of_frame / occluded / overlap)
  and applied_offset_px, and bake_labels returns a per-character worst-case
  summary in "offsets".
- New Blender probe tools/blender_tests/test_label_layout.py: one Fill+Stroke
  pair per labelled character (RK-1 object side), no pair above the 5% overlap
  limit across eight sample frames (RK-2), and label height continuity
  (RK-5, <= 5% between adjacent samples within a shot). Registered (29 -> 30).
- The probe also records, as a diagnostic, that the screen-constant size still
  steps 37.5% across a 35mm -> 50mm cut (12.25 px -> 7.66 px). That is a real
  defect in the "project a curve.size-long segment" baseline inside
  bake_labels, documented in the code; the fit (iterating on the glyph's own
  bound_box) did not stabilise yet, so it is deliberately not enabled rather
  than shipped unverified.
