fix(sec): stop shot_id from escaping the export dir, and stop the GUI wiping the scene

Two findings from the parallel safety audit, both reproduced before the fix.

- F1 (path traversal): ``shot_id`` is concatenated straight into file names
  (``blockout_<id>.mp4``, ``first_frames/<id>.png``, ``depth_shot_<id>/``), but
  ``ShotPlan.from_dict`` accepted any string. A plan (LLM output, a hand-edited
  project.bdproj, or a replayed audit log) carrying
  ``../../../../Users/Public/x`` made the exporter write outside its own
  directory. The contract boundary now validates the id
  (``[A-Za-z0-9_.-]{1,64}`` and no ``..``) and raises; the SDL load path reports
  it as finding S11 instead of crashing.
- F2 (destructive GUI): the panel's "generate previs" button cleared *every*
  object in the scene -- the cleanup does not respect the BD_ prefix -- so a
  user's own modelling disappeared with no confirmation and no snapshot. The
  full clear is now an explicit panel option (``bd_clear_scene``, default on so
  a clean previs still works), and when it is on the operator captures a
  ``before_build`` checkpoint first.
- Tests: tests/test_plan_shot_id.py (14 cases: legal ids pass, traversal /
  absolute / separator / CJK / over-long ids raise at the contract boundary,
  and a project file with a bad id yields S11 rather than an exception); the
  operator probe gains scene_clear_is_opt_in_and_snapshotted, which pins both
  halves (opted out -> the user's object survives and no snapshot is taken;
  opted in -> a snapshot exists and the object is removed).

python -m pytest -> 1065 tests, the only 6 failures are the parallel P14 branch's
knowledge/holdout WIP (unrelated to these files). All three operator-probe
checks are green.
