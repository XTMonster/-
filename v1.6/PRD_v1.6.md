## 1. 背景

BlockDirector 把剧本变成 Blender 白模预演视频，作为下游 AI 动漫生成的参考。v1.5 落地后链路能跑完、能对齐导演声明（E-run §5），但 2026-10-08 的两份现场读数暴露出**"预演参考"还不达标**（E-video §0：P0×2、P1×4、P2×3），且**83.6 分钟里 83.4 分钟在等模型**（E-run §3）。

用户提出三个新方向（本版主线）：

1. **元素统一**：白模预演视频交给 AI 视频生成时，元素（角色/道具/环境）要前后一致、可被下游锁定；
2. **节奏规划**：插件要理解并规划视频节奏、行为节奏、剧本节奏、速度曲线；
3. **视锥构图校验回路**：LLM 通过时间轴视锥矩形判断构图是否合理，不合理则告警，由 LLM 裁决是否修复，且执行过程中始终审查。

外加两份现场读数里的**存量缺陷修复**与一个几何变更：**角色身体改为圆柱形**。

## 2. 需求依据（每条需求后面挂证据，不许凭感觉立项）

### 2.1 元素统一（FR-A）

* 下游视频模型"复现所见比复现所说更精确"——几何/布局控制信号比提示词可靠（GPTunneL 工作流结论，R-构图 §2.3 转引）。
* 行业现状：灰模/白模参考视频已是 AI 视频的标准上游（Higgsfield 3D Jutsu、GPTunneL 3D Scene，R-构图 §2.3）；VACE 一类全控模型把控制信号规范化为**深度/姿势/布局/遮罩**四类可编码为 RGB 视频的信号，身份则由**参考图**承担（VACE 论文方法节，2025-08；Wan 2.2 VACE ComfyUI 工作流用 Depth Anything v2 从源视频取深度序列约束布局与遮挡，2025-10）。
* 身份与运动分离已是通行做法："深度图只保留运动和运镜，身份来自定妆照"（SunoMV 深度图重拍流程，2026-09）。
* 本项目已具备：逐镜 mp4、首帧、深度序列（16-bit PNG，0.1–50 m 归一化）、`shots.json`、`prompts.md`、`camera_traj.json`（AGENTS.md Phase 6 / 深度序列条目）。
* **缺口**：环境没建出来（E-video P0-1）使"空间一致"无从谈起；占位角色混进镜头（E-video P0-2）直接破坏元素一致；交付包里没有**跨镜元素登记表**与**逐元素遮罩通道**，下游拿不到"谁在哪"的锁定信号。

### 2.2 节奏规划（FR-B）

* 镜外节奏有可量化指标：ASL（平均镜长）——动作/惊悚 2–4 s、剧情 6–10 s、古典好莱坞 8–12 s；加速（镜长递减制造升级感）与减速是经典手法（Fiveable/Filmmakers Academy/Oboe 的 ASL 资料，2026 检索；Grokipedia「external rhythm」条：短镜 <3 s 加速、长镜 >8 s 减速，Pudovkin 1929 的节律对齐理论）。
* 镜内节奏已有雏形：`contracts/beats.py` 的 `ShotBeat.pace`（slow/normal/brisk）经 `beat_compiler.py` 折成引擎速度词（walk/run）；`motion/model.py` 内部已有 `_ease`；相机运镜已写 BEZIER 插值（`layer3_engine/cinema_engine/camera_motion.py:88-89`）。
* **缺口**：pace 只有三档且只影响走位速度；**没有速度曲线概念**（起停生硬，E-video P1-4 提到"事后错开会改变蓄-发-收节奏"——说明节奏是用户敏感点）；**没有剧本级节奏弧**（SceneBrief 有 arc 但不驱动时长规划）；**没有镜长单调性/跳切风险的诊断**。

### 2.3 时间轴视锥构图校验回路（FR-C）

* R-构图（深度调研报告）结论：**可行且方向正确**——学术对应"约束相机规划的逆用"（Virtual Cinematographer 1996 的约束表达式反过来就是校验器），工程对应 `bpy_extras.object_utils.world_to_camera_view` 的 NDC 投影逐帧采样，LLM 工程对应"验证器反馈回路"；关键分工是**几何层只报现象（带数值证据），语义裁决留给 LLM**（R-构图 TL;DR / §4.1）。
* 现状已有：`cinema/composition.py` 六项加权评分（PASS_SCORE=70）、`shot_auditor.py` 首/中/尾三帧审核、射线遮挡、可选 VLM 外回路（`vlm_review`）。
* **缺口**（E-video 实证）：构图门判红后**没有可执行的修复闭环**——9/13 镜 degraded，`E_CAM_001` 32 次，模型反复试仍不过（P1-1）；轴线判定用"当前两人连线"而非可观测量，13 镜无一幸免（P1-2）；审核是"一个分数"，不是"哪一项错了、错多少、怎么改"的结构化告警；**时间轴维度缺失**（只在三个离散帧上评分，没有曲线与事件检测）。

### 2.4 存量缺陷（FR-D）与圆柱身体（FR-E）

逐条来自 E-run §4 与 E-video §2/§3/§5，编号与修法见 §4 的 FR-D 表；圆柱身体是用户 2026-10-08 的显式指令。注意：v1.4 §7 D1b 曾裁决"躯干用圆角方体、不用圆柱"，理由是**等外接盒的圆角方体与圆柱世界 AABB 逐位相同**（`docs/evidence/d1b_body_shape/`）——本次变更正是利用这一点：**换网格构造，锚点/包围盒/构图常量一律不动**，风险天然有界。

## 3. 目标与非目标

### 3.1 目标（按优先级）

| 优先级 | 目标 | 对应需求 |
|---|---|---|
| P0 | 修复两份现场读数里的 P0/P1 缺陷，让 13 镜样片"能当预演参考" | FR-D |
| P0 | 角色身体改圆柱形，且不动任何锚点/构图/验收读数 | FR-E |
| P1 | 交付"元素一致性包"：跨镜元素登记表 + 逐元素遮罩通道 + 稳定 token 提示词 | FR-A |
| P1 | 时间轴视锥构图校验回路（结构化告警 → LLM 裁决 → 修复） | FR-C |
| P2 | 三层节奏规划（剧本弧 / 镜长档案 / 镜内速度曲线） | FR-B |
| P2 | 性能止血：超时配置化、重试阶梯、断点续跑 | FR-D（D-01/02/09） |

### 3.2 非目标（写清楚，防止执行者自作主张）

* **不改**冻结几何 1.70 m 与"头球相切"（ADR-0007）；圆柱化只换网格。
* **不改**任何验收判据的数值（PASS_SCORE=70、R001–R019 语义、ASL 只作诊断不作硬门）。
* **不引入新 LLM 通道**；不重写知识层；不动 hypergraph schema（hg/v2 冻结）。
* **不做** VLM 强制在线审核（vlm_review 保持可选）；不渲染真实材质（白模定位不变）。
* **不自己造投影矩阵**：一律复用 `world_to_camera_view`（R-构图 §5 的边角情形警告）。

## 4. 功能需求

### FR-A 元素一致性包（Consistency Pack）

| 编号 | 需求 | 验收判据 |
|---|---|---|
| FR-A1 | **环境最小骨架**：任何场景必须有地面 + 四周遮挡体 + 天空底色；`SceneBrief` 新增 **`environment[]`** 字段（与角色间关系 `space[]` 并列，不动其原义），环境元素走**可解析方位闭集**（`front/back/left/right/above/ground` × `near/mid/far` × `s/m/l`），氛围描述只进 `mood` 自由文本；解析失败**报 finding 并带回计划重问**，不静默跳过 | `unresolved_anchor == 0`；样片 shot_001 首帧能认出 ≥3 个环境元素（E-video P0-1 的判据） |
| FR-A2 | **元素登记表** `elements.json`：全片元素（角色/道具/环境件）一处登记，含稳定 id、显示名、颜色、形状、首次出现镜号；角色颜色从 cast 调色板**确定性分配**（同角色跨镜同色同形） | 登记表与 `shots.json` 逐镜角色列表一致；两跑同剧本逐字节相同（确定性） |
| FR-A3 | **逐元素遮罩通道**（可选导出）：每镜一条 mask 视频/序列帧——每角色固定纯色块、环境灰阶、无标签无文字；供下游 VACE 类工作流当 layout/mask 控制信号 | 导出目录出现 `masks/shot_00X/`；帧数与该镜 mp4 帧数一致；同一角色颜色与 `elements.json` 一致 |
| FR-A4 | **稳定 token 提示词**：`prompts.md` 每镜的元素描述引用 `elements.json` 的同一套名字与描述句（一段"元素表"头 + 逐镜引用），禁止同一元素在不同镜换说法 | `prompts.md` 里角色描述句与登记表逐字段对拍一致（复用 P15 的对拍测试机制） |
| FR-A5 | **角色定妆卡**（可选）：每角色一张标准机位首帧图，供下游当 R2V 身份参考的"白模侧对照" | 导出目录 `reference/characters/<name>.png` 每角色一张 |

### FR-C 时间轴视锥构图校验回路（Frustum Guard）

| 编号 | 需求 | 验收判据 |
|---|---|---|
| FR-C1 | **逐帧度量采样**：对该镜时间轴采样（隔帧 + 关键事件帧加密），用 `world_to_camera_view` 投出每个主体的 2D 包围盒与深度，depsgraph 求值后的 `matrix_world`（不读原始数据） | 纯层（度量/事件）零 bpy 可单测；bpy 层 headless 测试断言采样帧数与投影值 |
| FR-C2 | **六项单帧度量**沿用并扩展现有 `composition.py`：主体占比（景别回读）、三分偏差、headroom、lead room、边缘裁切率、可见比例（射线）；阈值**可配**并暴露三档风格预设（strict/standard/loose） | 度量定义与 R-构图 §3.2 表逐项对应；阈值进 config，不进代码常量 |
| FR-C3 | **曲线事件检测**：持续违规（超阈连续 ≥N 帧）、突变（两帧间占比跳变）、出画/入画事件（与剧本声明的离场时间 diff）、镜内景别漂移（声明固定景别但占比漂移 >±15%） | 四类事件各有合成样例单测；瞬时越界（<N 帧）不告警 |
| FR-C4 | **结构化告警 DTO**：`{shot_id, frame_range, type, subject, evidence{实测值,阈值}, severity(error/warning/info), confidence, declared_intent, suggestion_hint}`；**只报现象，不判死刑**；同镜同类合并（时间聚合），防告警疲劳 | DTO 有 JSON schema 与 serde 测试；E-video 的 13 镜样例重放时，"只剩眼睛"的 CU 镜产出 `framing_too_tight`（evidence 含头部占比实测值） |
| FR-C5 | **裁决回路**：审核失败时把告警（含分量数值）注入修复提示，模型改**一个**分量；提供参数化 `reframe` 动作（抬机位/改焦段/挪主体）；LLM 显式接受/拒绝每条告警，记录 `guard_verdict` 审计事件 | E-video 样片重跑：`audit_pass_rate` ≥10/12，`degraded` ≤1 镜（E-video §5 顺序 4 的判据） |
| FR-C6 | **镜头间校验**：180° 轴线改用可观测量（银幕左右序状态机：角色在画面左/右半区 + 朝向符号），与计划 `axis_note` 文字脱钩；跳切风险（相邻镜占比差 <10% 且视角差 <30°）作 warning | E-video 样片重跑：`E_AXIS_001` ≤2 次，镜 13 不再 `crossed`（E-video §5 顺序 5 的判据） |
